3. 我见过最费人的赛训流程

**正文**

```text
一场训练赛结束，教练组手上有四样东西：七页结算截图、一段录屏、一个手填的 Excel、一条营地链接。

要把它们变成"这局前期被压住了"，中间隔着：10 个人的 KDA、经济、输出、承伤，一个个抄进表格，再核对有没有抄错，再和上一场比。

抄完一般凌晨一点，人也麻了，最后复盘靠印象。

所以我做了个东西，把这段路接起来：

采集 → 本机识别 → 逐项核对 → 来源留痕 → 只读分析

四个坚持：

① 候选不写库
OCR 只出候选值，你确认了才成为记录。抄错这件事不会静默发生。

② 每个数字带来源
文件解码 / 引擎实测 / UI 采样 / 估算，四档写进界面。插值不假装成实测。

③ 全部在本机跑
127.0.0.1 起服务，一个进程、一个 SQLite、一个 data 目录。不连云、不用管理员权限。

④ 老对局有兜底
营地详情只留最近一个月，更早的局走七页截图 + 一段整局录屏，路径一样，只是识别在本机做。

Windows 装完双击就能用，不用装 Python。

带队的朋友可以说说，你们现在卡在哪一步：是没人抄，还是抄完了不知道看什么。
```

## 笔记 2｜方法论篇（Day 4，涨粉主力）

**标题**

1. 训练赛数据，先别看胜率
2. 31 局 51.6% 胜率，什么都说明不了
3. 做赛训数据，我只信这三个前提

**正文**

```text
"这个选手胜率 75%，所以他是核心。"

这类结论我见过太多次，八成是错的。

看训练赛数据，先问三个问题，再谈结论。

1）样本多大
31 局 51.6% 和 3 局 66.7%，不是一回事。看到"75%"先问一句：几局？

2）口径是什么
同样叫"参团率"，有人算击杀参与，有人算助攻参与；同样叫"经济差"，可能是终局差，也可能是 10 分钟差。口径不写清楚，两组数根本没法比。

3）来源是哪
截图 OCR 读的、营地面板拿的、回放文件解出来的，可信度完全不同。混在一张表里算平均，等于把误差当结论。

所以我们把六条规则写死在流程里：

候选不写库 / 冲突不合并 / 缺失不补零 /
部分不冒充终局 / 变更有审计 / 口径先于图表

展开说两条最容易被忽略的：

"缺失不补零"——缺的字段留空，不按 0 参与统计。少了就少了，不要用 0 把分母撑大。

"部分不冒充终局"——只有录屏快照的行标 partial，默认不进选手和团队统计；勾选后才显示，且分均经济、分均输出仍然是空的。

还有一个反直觉的：不要拿"训练量"和"比赛量"混着比。训练赛的对手强度、版本、选手是否全力都不可控，把它当排位数据看，很容易得出漂亮但没用的结论。

完整六条我做成了第二张图，需要的自取。

数据诚实不是道德问题，是能不能复盘的问题。
```

## 笔记 3｜功能篇（Day 9，转化）

**标题**（用「我做了一个…」句式，10 个字讲清品类）

1. 我做了一个赛训复盘工作台　← 实际发布用
2. 我做了一个不用联网的赛训工具
3. 我做了一个教练不用抄数的赛训工具
4. 26 个页面里，只有 4 个是采集

**正文**

```text
判断一个赛训工具值不值得用，我只看一件事：
采集之后，还剩多少东西能给你看。

因为采集是入口，不是价值。真正花时间的，是这些：

单局复盘 —— 这一局发生了什么，转折点在哪
训练纪录 —— 这批局的极值在哪一场，离均值差多少
跨局分析 —— 换一套阵容，赢率真的会变吗
战队档案 —— 这个对手强在哪、弱在哪
名单与状态 —— 本期谁在打，谁有可比样本
英雄榜 —— 池子多深，版本答案是什么
BP 概览 —— 我们的 BP 是不是被对手读透了

七块，全是在"数据已经进来之后"才有意义的东西。

我做了 26 个页面，采集只占 4 个。剩下的是对局、战队、选手、英雄、BP、赛训，全是只读分析——它们不改你的数据，只负责把事实摆出来。

每块分析背后都有一条口径：样本几局、覆盖多少场、哪些是采样、哪些是插值。写不出来就不给结论。

每一张图都是逐块截的，标了它回答的问题和数据来源。

采集是入口，分析才是主体。
它不替你下结论，它把下结论要的每一条事实准备好，并且每条都能追到出处。

Windows 装完双击就能用，不用装 Python，数据全在本机。

装法在主页。
```
