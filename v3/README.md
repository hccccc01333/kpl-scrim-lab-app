# 赛训数据平台 V3

V3 的页面、样式和分析接口位于本目录。**唯一入口是根目录的 `server.py`**：
它把这里的路由并入同一个 FastAPI app，并把 `public/` 挂到 `/static`。

```powershell
python server.py
```

打开 http://127.0.0.1:8766/。右上角可切换浅色、深色主题；问号打开使用教程，共八课（采集、补录字段、复盘、跨局、BP、选手与对手、赛训与报告），可以按顺序做，也可以单独重看某一课。

`serve.py` 仍保留 `--port` 启动方式，仅用于本地开发调试（不带采集写接口）；不再是产品入口。演示环境改用根目录的 `server.py`，见下。

## 数据与演示

- 真实数据模式读取原有训练赛数据库、对局包、营地面板与回放。战队、选手、计划、训练、对局校对和确认操作会写入共享数据，请按页面提示核对。
- 演示数据不再作为工作台入口；需要截图或测试时，仍可用隔离的 8773 开发环境（`KPL_DATA_DIR` 指向本目录 `demo-data`），它不会写入正式库。模拟对局、阵容、经济、坐标和团战事件均为虚构。
- 对局、选手及版本页面支持页面上的“数据范围”。营地专题与空间回放使用全部已关联面板，会在页面注明这一点；营地来源可能包含非训练赛。
- 文件导入先预览再确认。V3 保留预览原文件，已导入的同一文件不会重复计入；表格来源需在数据范围中启用。
- 对局迁移只新增真实来源中尚未迁移的基本信息，不覆盖既有记录，不猜测对手、选手身份或禁选顺序；需要人工核对的字段可在待确认页处理。
- 身份只有一条链：**游戏ID（营地昵称）→ 选手ID → 战队**。入口在「赛训 → 数据准备 → 建档」顶部的「身份对照」，对手归属页每名选手也有「命名」。写入只落 `player_accounts` + `players` + `teams`（`identity_service.py`），读时解析，历史对局文件不改；删选手会连他的游戏ID映射一起删。

## 使用方式

对局、战队、选手、英雄与 BP 页面顶部提供对应分析的直接入口；板块首页同时展示关键图形，手机端的分析入口可左右滑动。选手认领可把对局昵称与本队名单连接；对局详情可录入人工确认的 BP，顺序不会从营地阵容推测。空间位置、团战、经济、选手状态、英雄池、终局装备等分析在相关板块内查看。页面优先展示图形、卡片、样本量与计算说明，所有数据表格默认收起，按需展开核对。

经济兑现排除了未满十分钟的对局；资源争夺不混入推塔事件；训练效果只使用本队且来源有完整年份的记录。经济曲线、空间距离、观察性前后比较各有局限，页面会说明。

## 当前边界

终局装备分布可查，但装备成型时间和装备收益分析仍未实现。截图/录屏采集、数据清洗建模及部分旧版原始记录管理流程尚未完整迁入 V3；它们不应被理解为已经完成。当前结构化迁移只处理新增对局的基本信息，不创建无法可靠识别的阵容或手序。
