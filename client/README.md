# 赛训台 · 桌面客户端

独立于工作台的桌面客户端。工作台继续负责数据、采集、导入与 API；客户端是给分析师和教练组读数据、看复盘、查选手与战队的桌面入口。两者共用同一套工作台 API；单局深度分析的计算口径已移植到客户端（`lib/analysis/`），并与 v3 网页逐项对照。

## 单局深度

比赛详情页已原生覆盖 v3 的单局分析：

- 本局结论、总量带、阶段对比、可拖动比赛脉搏、关键节点
- 十人面板（对位雷达 / 队内份额 / 入侵率）、中野辅集结与入侵归因
- 团战地图、团战贡献、掉点反事实损失
- 五人阵线、分路热区、对位纵深（深区 / 半区）、完整 BP 板与锚点导航

位置与回放事件来自 `GET /api/positions/:key`、`GET /api/replay/:key`；缺数据时页面给出具体原因，不补零。页面顶部的「网页版」按钮可在独立窗口打开同一局的 v3 页面，便于并排比对。

## 选手 / 战队 / 英雄 / BP

M2 已把 v3 的分析板块搬进客户端，左侧一级入口下带二级页签：

- 选手：名单与状态、选手档案（筛选 / 排序 / CSV）、选手与位置、选手对比、个人页（分位 / 画像 / 逐局 / 对位 / 关键局 / 搭档 / 英雄池）。
- 战队：档案、详情（评分构成 / 雷达 / 分路资源 / 对位 / 英雄池 / BP / 组合 / 四象限）、风格、阵容、训练。
- 英雄：英雄榜、详情（位置 / 搭档 / 三人组 / 出装 / 选手与战队使用 / 均值对照 / 成长 / 时间 / 对位）、对比、组合。
- BP：概览（条件画像 / 选禁 / 英雄透镜 / 组合 / 阵营 / 逐局 / 训练日）、战队 BP、教练档案。

选手认领、战队改名 / 合并、教练姓名录入、训练计划与训练课编辑仍是工作台写操作；客户端只读展示。BP 数据只含营地终局名单，不推断禁选顺序。

## 对局分析（M3）

「对局」模块已按 V3 当前可见页签搬到客户端：

- 跨局分析：全量向量算总体，10 张结论卡、分路对位、逐局火花线、参照分布、筛选/圈定与 CSV。
- 智能找局：按对手、英雄、结果与排序挑局。
- 精选对局：按复盘价值挑出最值得回看的经济时间轴。
- 训练纪录：最长/最短、最大/最小终局金差、最高击杀/KDA/分均经济、经济最反复。
- 版本对比：按版本或训练组看局数、胜率、时长与平均金差。

V3 里没有可见入口的 `#topic/*`、`#study/*`、研究型报告库、经济转折、对手侦察不进入客户端。

## 赛训（M4）

「赛训」只做 V3 当前可见的只读分析：

- 训练计划：8 周负荷、目标达成环、训练节奏热力、最近训练课、只读排期。
- 训练效果：干预前后对照与效应量，不提供登记表单。
- 训练课：目标、关联对局、赛后复盘、出勤与对手简报，只读并可打印。
- 复盘与报告：报告库、训练周报生成入口、周报只读与打印 / PDF。
- 报告快照：按保存时的列与口径展示，不随源数据变化。

训练计划、训练课、出勤、目标、数据准备等写操作仍在工作台；客户端不提供假编辑入口。

## 开发

```bash
cd client
npm install
npm run dev
```

国内网络如果卡在 Electron 二进制下载，先设置镜像：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install
```

首次启动会打开连接页。默认地址：

```text
http://127.0.0.1:8766
```

本地演示或另一个工作台实例可以直接填写对应端口，例如 `http://127.0.0.1:8790`。

## 构建

```bash
npm run typecheck
npm run build
npm run dist
```

`npm run dist` 输出 Windows 安装包：

```text
client/release/赛训台-<版本>-setup.exe
```

国内打包如果卡在 NSIS / winCodeSign 下载，使用：

```bash
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npm run dist
```

安装包按用户安装，不需要管理员权限；未做代码签名，首次运行可能触发 Windows SmartScreen。分发给队内时建议通过微信 / 网盘发送，并附 `.sha256`。

## 结构

```text
src/main/       Electron 主进程：窗口、托盘、单实例、设置、API 代理、工作台启动 / 单页打开
src/preload/    contextBridge API
src/renderer/   React 界面：概览 / 比赛 / 选手 / 战队 / 英雄 / BP / 赛训 / 设置
  lib/analysis/ 单局、选手、战队、英雄与 BP 计算内核（与 v3 同口径的纯函数）
  components/charts|analysis/ 图表原语与分析页骨架
```

客户端通过主进程代理访问工作台 API，避免 `file://` 页面直接请求本机 HTTP 的跨域问题；渲染层不直接拿 Node 权限。

## 边界

- 默认只连本机；也可以在连接页填局域网工作台地址（工作台需要允许远程 Host）。
- 客户端内置王者营地采集：`mp-redirect` 赛后十人面板 + 官方回放，按 `gameSeq` 配对；无缺失值自动入库，有缺失值才进入「缺失值审查」，支持一键通过。
- 营地只提供最近 31 天的战局详情；更早的局在客户端标记「营地无详情」且不会被自动勾选，通过「截图/录屏补录」打开工作台 OCR。客户端不实现截图/录屏上传与 OCR 审核。
- 批量入库会把营地条目的 `gameSvrId` / `relaySvrId` / `uniqueRoleId` 一并交给工作台，由工作台自动补官方回放；旧通道缺回放文件时，采集页会显示「补齐官方回放 N 局」。
- 截图、表格、录屏等其它采集入口，以及数据准备 / 训练计划 / 训练课编辑仍在工作台完成；设置页和左侧「工作台」入口可互相跳转。
- 工作台可通过 `kpl-client://open` 拉起客户端；客户端通过 `kpl-client` 协议注册，安装新版本后生效。
- 数据留在工作台所在机器与本机内存中，不上传云端，不内置遥测。
- 设计方向：亮色纸本分析台 + 深色比赛房；数字使用等宽字体，图表直接标注，不做营销页式大留白。
- 客户端自动更新尚未接入：发新版本时用新安装包覆盖安装，`settings.json` 与连接地址会保留。
