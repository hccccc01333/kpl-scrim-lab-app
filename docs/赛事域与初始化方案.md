## 0. 结论摘要

1. **决策按推荐定稿**（见 §1），不再逐条重议。
2. **盘点发现：赛事设施大半已存在**——赛事表本身就是「备战周期」语义（训练归集窗口 + 正赛时间口径），对局直连赛事、导航门控、按赛事过滤的分析仓库都已有实现和测试。本方案是**把分析域补齐、打通前端**，不是从零建。
3. **M1/M2/M3 已落地（2026-11-23）**：M1 全量（scope 层、接口隔离、前端赛事参数与顶栏赛事名、初始化清单 v1）；M2（存量系列批量归属面板、正式比赛录入：结果级+阵容级表单、平台填表为主）；M3（规则 effective 接入命中判定、boBp「含其他赛事历史」开关、`event=` 深链与赛事 chip、`tiers.py` 等级映射 + 队伍资料 league 字段）。BP 顺序级录入（bp_overrides + orderPending 口径）、league 表单字段、全分析页赛事 chip 均已落地；正赛录入角色定稿为「只做记录」（审计里的 P1-3 相应撤销，不进分析语料是设计而非缺陷）；P2-2 赛事生命周期（状态切换 + 归档只读）、解锁 v2（锁卡/进度/侧边栏灰显）、P2-1/P2-3 已落地；P1-4/P1-5 已落地。至此赛事域方案全部收口，V3 完整版就绪。收口批次：双通道统一（formal_link 转正 + 待补全预填）、KPL 拉取、赛季切换向导、跨赛事档案端点、正赛章、性能基准（100 局 0.10s）、操作指引。
4. **对此前讨论的一处修正**：§4 统一 scope 层、§5 接口隔离（series/cross/analysis）、§6.1-6.2 前端赛事参数与顶栏赛事名、§7 初始化清单 v1；M2（存量归属工具、正式比赛录入）与 M3（规则 effective、跨赛事开关 UI、等级映射）待排期。
4. **对此前讨论的一处修正**：归属不挂系列赛，**维持现状「对局直连赛事」（`match_records.competition_id`）**；系列赛的归属由其对局集合推导 + 冗余列校验。比「系列赛继承」少一层间接，且与已建成的双时间口径一致。

## 3. 归属模型（定稿）

```
competitions（赛事 = 备战周期）
 ├─ match_records.competition_id   ← 事实源：单局直连
 ├─ training_series.competition_id ← 冗余列（新增）：= 其全部对局的赛事，编组/补局时校验一致
 └─ 未归属对局（unfiled）           ← 不入任何分析域，只进采集质量统计
```

- **训练赛口径** = 直连 ∪ 归集窗口 ∪ 手动挂载（复用 `competition_training_matches` 现有规则，抽成公共函数供 scope 层调用）。
- **正赛口径** = `formal_from / formal_to` 窗口（复用 `competition_formal_matches`）。
- 赛事生命周期：`planned → ongoing → archived`（archived 只读，规则/阵容按当时 effective 冻结）。
- 一个系列只归一个赛事；跨赛事对局混编在编组接口报错并提示拆分。

## 4. 统一 scope 层（本方案的关键工程）

**目标**：任何分析取数，都从同一个函数拿「当前赛事的对局键集合」，杜绝某条查询漏过滤。

1. `workspace_store.Workspace.competition_scope_keys(competition_id, kind='training'|'formal')`
   —— 把 `competition_training_matches / competition_formal_matches` 的口径抽成键集合函数（带结果缓存，按 competitions.revision 失效）。
2. `analysis_api.CompetitionScopedRepository` 改用统一口径（现状只认直连，归集窗口里的对局会漏）。
3. `v3/serve.py` 全局快照仓库增加 scoped 包装（复用 `CompetitionScopedRepository` 思路）：`repository(request)` 检测 `competition` 参数返回过滤视图，默认行为不变。
4. 纪律：**新增分析接口一律从 scoped 仓库取数**；验收用「赛事 2 只挂 1 局」逐页断言（见 §10）。

## 7. 初始化清单 v2（右上角入口弹层，数据驱动判定 + 完成提示）

| 步骤 | 深链 | 自动完成判定 |
|---|---|---|
| 1 选择/创建赛事 | `#competitions` | competitions ≥ 1 且已设当前赛事 |
| 2 战队与选手档案 | 战队/选手页 | 队伍资料完整 + `competitions.own_player_ids` 非空 |
| 3 规则配置（可跳过，标"推荐"） | `#rules` / 组合池 | `combo_pool.has_saved()` 或规则中心 counters 非空 |
| 4 采集第一局 | `#capture` | 当前赛事（含 unfiled）对局 ≥ 1 且质量检查通过 |
| 5 编第一个系列赛 | 系列赛编组 | 当前赛事 `training_series` ≥ 1 且已确认 |
| 6 语料阈值 | 分析页 | 当前赛事已确认对局 ≥ 阈值（默认 20，按等级可调）→ 解锁跨局 |

- 判定全部由数据计算，**不设手动打勾**；按当前赛事展示进度；新赛季/新赛事自然重置。
- v2 形态：首页不再摆清单卡，改由右上角「初始化清单」入口打开弹层；某步从未完成变为已完成时弹「你已完成 …」提示；旧版分步操作教程已删除（界面已大改，旧步骤不再匹配）。
- v3 重设计（2026-11-26）：入口改名「上手引导」，由原生 `<dialog>` 承载（焦点圈定 / Esc / 背景 inert 交浏览器），内容改为三阶段（定赛事、建底稿、出结论）+ 单一「下一步」卡。进度只计 5 个关键步骤（赛事 / 本队档案 / 对手库 / 采集 / 编组）：规则配置明确标「可选」且不计入进度（内置规则本就可用），语料阈值改称「语料深度」并作为持续积累项——因为解锁 v2 的口径是确认 1 个系列赛，不是攒够 20 局，清单不能再给出矛盾的「待完成」。「现在可用」直接读 `/api/v3/unlocks`，与分析页同一口径；采集数明确标「本赛事」以区分全局采集量。未选赛事时下游步骤灰显并统一引导先选赛事。

## 8. 正式比赛数据录入

- **三档深度**：结果级（对手/比分/日期）→ 阵容级（十人英雄+位置）→ BP 顺序级（逐手 ban/pick）；质量标记复用采集 `orderPending` 口径，缺什么提示补什么。
- **表单**：对手（自动建 opponent_team）、日期、比分、每局阵容、可选 BP 手序、关联赛事（默认当前 ongoing，正赛须落在 `formal` 窗口内）、`data_type=formal`。
- **去重**：对手 + 日期 + 比分指纹；与营地同步冲突时以同步为准（BP 手序自动铺比手录准）。
- **归集**：写 `match_records.competition_id`；日期落在 `formal_from/formal_to` 外时警告并允许改窗口。
- **录入形态定稿（赛训组倾向）**：平台内直接填表（分档表单）为主；Excel 固定模板批量导入降为可选后续，冷启动仍可用。
- **录入角色（2026-11-23 定稿，采纳 A 起步）**：正赛只做记录——归属赛事、进对手库、赛事页展示战绩；**不进分析语料**（大场/跨局/BO 习惯仍只吃训练赛语料，正赛局缺 POV/十人明细，混入会稀释结论）。BP 顺序级写的 bp_overrides 先存待挂，哪天该局进了语料自动生效。预留 C 口子：将来可加显式开关把正赛纳入分析（默认关）。

## 9. 使用者等级（联赛映射表）

- 战队资料加 `league` 字段：可配置列表（KPL / K 甲 / 女子联赛 / …），**不写死枚举**。
- 映射表：等级 → ①正赛数据源能力（营地同步可用性）②外部事实表适用性标签（KPL 克制表对女子赛仅"meta 参考"）③解锁阈值默认值 ④赛事模板（名称/窗口）。
- 新增等级只改映射表，不改代码；对应 UI（采集页能力入口、事实表结论标注）按映射渲染。

## 10. 验收方案

1. **隔离验收**：建赛事 2，只挂 1 局；逐页断言（采集/对局/系列/大场分析/跨局/BP 工作台/英雄/选手）不出现赛事 1 任何数据；切回赛事 1 数据完整。
2. **双口径验收**：归集窗口内未直连的对局进训练赛口径；正赛窗口对局进 formal 口径；unfiled 不进分析。
3. **规则生效验收**：赛事 1/2 配不同克制规则，同一组合命中结果按当前赛事不同。
4. **开关验收**：BO 习惯「含其他赛事历史」开/关，样本量与样本清单随之变化，默认关。
5. **迁移演练**：存量 `training_series` 回填 `competition_id` 脚本 + 回滚；旧库缺列自动补列路径验证。

## 12. 正赛 Excel 导入：三 sheet 固定模板字段清单（2026-11-23 定稿）

- **Sheet1 对局（一局一行，队伍级）**：基础＝日期/对手/赛段/BO/局序/我方阵营/赛果(我方胜·负)/时长/版本号；开局资源＝一血/一塔/10 分钟经济差/暴君/主宰/黑暗暴君/风暴龙王/推塔(我方·对方)/击杀合计(我方·对方)。团战与切 C 类**不收**（训练赛靠回放事件算，手录填不出，等正赛有回放自动补）。
- **Sheet2 选手（一人一行，十人明细）**：定位键＝日期/对手/局序/阵营/位置/英雄/选手名(营地 ID 选填)；数据＝击杀/死亡/助攻/总经济(或分均)/输出伤害/承受伤害/参团率/评分。
- **Sheet3 BP 顺序（可选，一手一行）**：日期/对手/局序/手序/阵营/动作(ban·pick)/英雄——逐手是结构化数据，配 4ban/5ban 规格严格校验，收进模板。
- **校验与衔接**：Sheet2/3 按（日期+对手+局序）联接 Sheet1；十人同进退；每局 ban/pick 数按规格校验；深度按填充度判定（只 Sheet1＝结果级、+Sheet2＝阵容级、+Sheet3＝BP 顺序级）；BP 未填＝orderPending 口径提示。
- **落地方式**：平台提供模板下载（示例行+表头冻结+枚举下拉）；导入走 sheet 导入 staging→审查流；线上表格（official-entry）同步补齐同款字段，两通道字段一致。实现排 P3，需点名启动。
