## 页面组织

一级导航按对象和具体功能分类，参考 [KPL 赛研导航源码](https://github.com/hccccc01333/kpl-research/blob/main/kpl_insight/frontend/assets/common.js)的组织方式，映射到本项目已有训练赛功能。

- 首页：`#overview`。
- 比赛：`#matches`、`#featured`、`#records`、`#desk`、`#new`。
- 战队：`#team`、`#stats`、`#training`、`#roster`、`#topics/tempo`、`#topics/swing_windows`、`#topics/session_summary`、`#reports`。
- 选手：`#players`、`#identity`、`#topics/player_form`、`#topics/player_pairs`、`#topics/resource_efficiency`。
- 英雄：`#heroes`、`#combos`、`#topics/hero_benchmark`、`#topics/hero_pool`、`#topics/hero_combos`。
- BP：`#bp`。
- 对比：`#compare/player`、`#compare/hero`；`#compare` 兼容进入选手对比。对象名可作为第三段保留。
- 深入分析按上述功能分散；统计与模型实验 `#lab`、`#models` 在数据菜单，旧 `#topics` 默认进入英雄池。
- 数据：`#capture`、`#channels`、`#import`、`#screenshots`、`#recordings`、`#replays`、`#datasets`、`#clean`、`#sources`。

`#analysis` 兼容为“全部功能”目录，不再作为一级分析分类。详情页跟随所属对象：比赛详情归比赛、选手详情归选手、英雄详情归英雄、对手档案归战队、采集通道详情归数据。

每个一级入口在桌面端点击旁边的展开按钮显示子页；总览底部还有一张按任务分组的完整功能地图，所有页面都能直接进入。赛训专题使用 9 张专题卡直接运行，不把专题藏在单选下拉框里。

统计实验先给 6 个场景（分布、趋势、异常、两组对比、相关性、聚类），点卡直接运行，默认使用全部已确认比赛；数据集、方法、指标、分组和筛选收进“高级设置”，样本表收进“查看本次样本”。模型实验同理，场景为指标解释和赛前预测。

选手和英雄页用卡片网格展示现有字段：每张卡标出样本数，胜率、KDA、分均经济/输出直接展示，不因样本少而隐藏功能；筛选、汇总表和逐局数据可折叠。点卡片进入选手/英雄详情，含 KPI、指标走势、常用英雄/使用选手和最近比赛。对比页支持选手或英雄双选，按 KDA、经济、输出、参团和胜率做数值与差值对照。

比赛、选手、英雄和数据集使用卡片模板：比赛档案是比赛卡片（日期、对手、比分、结果、时长、来源、完整度），表格视图折叠；英雄/选手是带英雄头像的卡片网格，点卡片看逐局记录；数据集是卡片列表，操作按钮在卡底。

比赛卡片进入对局详情页：有单局数据包时，详情页直接呈现单局档案（旧 `#panorama/<key>` 自动转到本页）。档案把官方 30 秒经济点、资源/建筑事件、逐秒坐标、十人官方评分和 .abc 出装时间线拼到同一屏：经济脉搏可按时间拖动，事件河流独立成轨，战场热区支持双方/单队/单人切换，轨迹随时间推进由浅到深，另有十人热区小图矩阵，可从任何一张选手卡回到主地图。官方事件不含英雄击杀、建筑事件没有坐标，页面和接口都显式标注，不用资源事件冒充击杀。接口为 `GET /api/review/{key}`；详情页底部保留 BP 补录、截图装备、十人完整数据和数据提示。没有单局数据包时仍回退到原有比分、阵容、经济曲线和击杀记录页。团队复盘页有战绩摘要、经济节奏卡（覆盖、终局差、10 分钟领先和走势线）、分路/BP/资源表和对手档案卡片。

扩展页面继续按现有字段复用：顶栏全局搜索（选手、英雄、比赛、功能）；对手档案（交手记录和对手英雄）；精选对局（领先被翻、逆转、经济接近、经济反复、高击杀）；训练纪录（时长、比分、经济差、波动）；BP 分析（禁用、选用、先后手）；英雄组合与双人搭档；选手/英雄详情雷达图和装备记录。BP 录入先选分路再选英雄，英雄按常用分路过滤；分路映射在 `web/hero-lanes.js`，只作为录入筛选，不写入 BP 数据，新英雄或未收录英雄在“未分类”中兜底。BP、装备、资源是条件字段，填了就有，没填显示空态。

比赛档案和全局搜索已改为服务端分页/搜索（`limit/offset/q/total`），首屏 24 张卡、加载更多；换页不一次渲染上千张卡。批量导入支持 CSV/TSV/XLSX/XLSM，先预览列映射和置信度，再确认落到 `data/imports`；身份绑定按每局左右方自动分成两队：本队昵称可映射到稳定选手 ID，对手昵称单独保留；名单为空时可直接把昵称创建为队员，只影响分析视图，不改原始比赛。别名只作用于本队阵营，避免对手同名昵称被误并。详情页提供“打印 / PDF”；`/api/health` 返回数据路径；`启动工作台-后台.vbs` 隐藏启动 `scripts/watch_server.py` 并在异常退出后自动重启，`停止工作台.bat` 结束看护与服务，`启动工作台-守护.bat` 保留为前台入口。

总览以真实最近比赛、阵容、比分和分析问题为入口；路径为比赛 → 单局 → 选手/英雄 → 对比。采集页直接创建本局，保存后可直接进入本局复盘。`#capture` 是采集入口；`#desk` 已下线并重定向到 `#matches`；`#clean` 作为独立清洗页保留，同时在数据集页提供“清洗并建立数据集”入口。`#stats` 与 `#training` 现在指向新版数据看板；`#channel/<id>`、`#edit/<id>`、`#review/<id>` 继续工作。

底层仍是“采集 → 清洗 → 数据集 → 分析 → 建模 → 报告”，但一级导航按赛训组的日常任务组织，不把流水线编号强加给用户。

## 工作流程

1. **采集**：一局一个采集通道，表格、截图、录屏报告和回放挂到同一局。截图、录屏与回放保留各自上传及校对页；采集数据只作为候选草稿，审核保存后才写入正式比赛记录。
2. **比赛**：比赛档案保留每份来源记录，卡片直接给出赛果、经济差、时长与缺失项，可就地补全对手/时长/赛果；逐场进入对局详情查看十人明细与过程证据。未知胜负不会被当成失利。
3. **分析**：选手、英雄与阵容、团队复盘、赛训专题、数据看板和统计实验。清洗数据集可直接用于统计与专题研究；缺少身份、分路或过程覆盖时保持为空，不拟造结果。
4. **研究**：对比赛记录、单局表、截图候选或已有清洗快照画像，保存独立数据集；模型实验保留岭回归与赛前阵容模型的时间留出验证；统计、模型与专题结果导出 CSV / HTML，保留计算条件和数据版本。
5. **设置**：维护战队名单、字段与来源；身份未绑定的昵称只作来源分组，不产生已确认选手的长期结论。
6. **备份**：顶部“备份项目”包含原采集工作台备份、单局分析包和清洗数据集。原始录屏目录及 CLI 表格导入目录需单独备份。恢复按已有 ID 跳过，不覆盖已有研究快照；跨库合并不是单个原子事务，重复恢复仍按 ID 去重。

## KPL 赛研功能适配

参考项目：[hccccc01333/kpl-research](https://github.com/hccccc01333/kpl-research)。本次核对的公开提交：`59f776c364ee03d2d298d8923ce8e6233bae234f`。

适配到本平台的专题如下。计算输入均为本地训练赛记录，不载入参考仓库的职业赛事统计结果。

- **选手 × 英雄参照**：参考 `hero_perf_app.js` 的同位置、同英雄基准与分位设计。界面显示中位、较高、高位水平（底层对应 P50 / P75 / P90）；训练赛按实际分路组织参照池，少于五行不显示分位，并列出参考人数和行数。
- **近期状态与稳定性**：参考选手深度档案的近期表现、地板、上限和波动维度。训练赛输出近期五局均值、样本数、标准差、低水平/高水平（P10/P90）和四分位距。
- **英雄池与使用集中度**：沿用 `team_bp_app.js` 的集中度公式（HHI = Σ(p²)）、有效英雄数 `1/HHI`，补充使用频次、头部占比和熵。界面显示为“英雄集中度”。
- **资源与产出**：对照经济占比、输出占比与伤害转化，逐行提供比赛入口；职责不同的选手不直接排综合能力名次。
- **阵容组合与 Lift**：沿用同队组合实际共现 / 独立选用基线的设计。只使用完整五英雄阵容，至少共现两次，胜率分母只含已知胜负。
- **双人搭档**：参考选手档案的同队搭档维度；只使用稳定选手 ID，拒绝把昵称相同当成身份已确认。
- **前期与优势转化**：参考系列证据分析中的分时检查点。训练赛计算 5/8/10/15 分钟经济差及十分钟领先后的已知赛果；不向录屏覆盖范围之外外推。
- **经济转折窗口**：参考 `analysis/series.py` 的连续方向窗口。以经济差作为观察代理，输出起止时间、变化幅度和比赛证据，不冒充训练赛胜率模型。
- **训练组证据汇总**：按明确填写的日期、训练组和对手组织训练记录，统计有效赛果与数据覆盖，不推断正式赛事赛制。

不移植职业赛程、联赛排名和系列赛比分推演。职业赛事预训练权重不直接用于训练赛。

## 当前限制

- 昵称未绑定的记录只能作来源分组；身份绑定只影响分析视图，原始比赛记录仍保留原昵称。
- 批量导入先自动推断表头，预览页可逐列改映射后再确认；列名不标准时不必先改表头，CLI profile 仍可用于复杂宽表。
- 缺少实际分路时不生成同位置基准；缺少资源事件或过程覆盖时不推断比赛内动作。
- 清洗快照保留行级数据；过程专题仍引用对应原始比赛的时间轴，尚未冻结独立的完整视频与时间轴版本。
- 预览限制为 200 行，数据表预览为 1000 行；清洗计算最多 30,000 行。
- 训练组汇总需要明确训练组及对手字段，不根据日期自动拼成一场系列赛。
