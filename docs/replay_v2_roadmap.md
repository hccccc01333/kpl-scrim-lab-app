# 回放分析 V2 路线

V1 已交付：完整事件流（88,627 条命令）、检查点金币/KDA/等级、插值曲线、
四档置信度标注、版本档案配置化。V2 目标是把“逐帧状态”和“战斗因果”补上，
并接入产品页。所有新增数据必须带来源与置信度，估算值不进入正式统计。

## V2-A 实时位置（外部堆 transform）

- 目标：十人逐帧 X/Z，误差 ≤5% 地图跨度，用 3 个以上小地图采样点验证。
- 线索：hero 对象（arena）在 `+0x2A0/+0x508/+0x628/+0x6E0/+0x728/+0x7C8`
  指向外部堆 `0x7311…`；arena 内的 `+0x278/+0x27C/+0x280` 是出生锚点。
- 验收：同一暂停态下候选字段与 `u=(x+60000)/120000, v=(z+60000)/120000`
  的小地图坐标残差 ≤0.05；播放 3 s 后移动英雄变化、静止英雄不变。
- 失败回退：只发布“小地图采样位置”（UI 采样），不发布逐帧坐标。

## V2-B 逐帧血量

- 目标：十人逐帧 HP 比例，尽量给出绝对 HP；缺失必须标 unknown。
- 路径：
  1. 外部堆属性对象（优先，与 V2-A 同一组指针）；
  2. 更多 UI 血条采样（`ui_hp_samples/`）；
  3. 检查点归一化 HP 对（`+0x08/+0x10`）做锚点。
- 验收：与 UI 血条/面板最大血量对拍，误差 ≤5%；不得用插值冒充实测。
- 现状：21 个实测样本（0.59% 帧），其余 unknown。

## V2-C 战斗与击杀归因

- 目标：击杀窗口 + 候选参与者 + 战斗密度；不伪造精确击杀时刻。
- 输入：`PLAYER_ATTACK` 7,538、`PLAYER_ATTACKWITHOBJ` 4,348、技能 1,472、
  CC 6,258，以及检查点 KDA 差分。
- 置信度：`derived-interval`（只有 KDA 差分）、`derived-candidate`
  （事件支持参与者）、`unknown`。
- 验收：所有击杀窗口都有 KDA 差分支撑；候选参与者注明证据；不声称帧级击杀。

## V2-D 出装与技能时间线

- 目标：每人出装顺序、关键装备时间、累计花费（价格已知时）、6 件套时间；
  与结算装备对比。
- 输入：`BUYEQUIP` 547 条 + 装备价格表（若有）+ 结算视觉读数。
- 去重：购买通知有重复/系统 tick，必须按 flag 与时间去重并记录规则。
- 验收：累计花费不超过相邻检查点金币增量；最终出装与结算一致或标注差异。

## V2-E 产品化

- “检查点状态（引擎实测）”区块：金币/KDA/等级/HP，缺失显示“—”。
- “V2 状态时间轴”：位置/血量/战斗/出装四轨，支持拖动与来源标签；
  位置轨只展示通过 V2-A 验收的数据，否则降级为小地图采样。
- 所有区块沿用四档来源：文件解码 / 引擎实测 / UI 采样 / 估算。
- 版本档案：新增客户端版本按 `docs/replay_profiles.md` 走流水线，失败关闭。

## 依赖与风险

1. V2-A/V2-B 依赖外部堆抓取；若指针目标不稳定或对象已回收，回退到 UI 采样。
2. 战斗归因没有伤害/kill 命令，只能到“候选”级；产品文案不得写成确定击杀。
3. 装备价格表若不完整，累计花费只对已知价格求和并标注覆盖。
4. 任何新增字段都要先过对拍，再进入页面；不用估算值填充实测列。

## V2-F 可部署化（2026-11-04）

验收标准：**别人 clone 仓库、只给一个 `.abc`，不装游戏、不连设备，也能跑出这条时间轴。**

原实现不满足：`replay_v2_api.DEFAULT_DIR` 指向
`data/replays/_analysis/live_20261104/v2_timeline`，那是本机研究产物；
换一台机器，接口只会 404。

改造：

- 新增 `replay_v2_build.py`：按局构建，输入 `--abc`（现场解码事件）或
  `--events`（已有目录），可选 `--checkpoints`；产物写 `data/v2/<abc_sha256>/`
  （`timeline.jsonl` + `meta.json`），字段与旧时间轴一致，缺失一律 null。
- `replay_v2_api` 改为按 `replay_id` 找 `data/v2/<sha>/`，旧的 `_analysis`
  目录只作开发回退；找不到时返回 404 并给出可执行的构建命令。
- 装备时间线 `_load_builds` 找不到目录时返回空表，不再抛错——页面必须能渲染。

已生成两局：

| 局 | 层级 | 行数 | 说明 |
|---|---|---:|---|
| `d74c2bed…`（161129） | events + checkpoints | 7,010 | 5 个检查点 × 10 人，金币/KDA/等级为引擎实测 |
| `017e0117…`（163751） | events-only | 10,260 | 没有采样，gold/KDA/level 全部 null 并标 unknown |

**层级命名**：Tier 0 = 只有事件；Tier 2 = 事件 + 检查点。页面必须按
`meta.tier` 与 `fields_missing` 显示"本局缺什么"，不能把 null 画成 0。

### 自动构建与装备时间线（2026-11-04 补齐）

- 导入 `/api/replays/import` 成功后启动后台线程，从 `replay_files` 取 `.abc`
  字节流构建 `data/v2/<sha>/`；已存在则跳过，失败只记日志、不影响导入。
  实测 741 KB 回放耗时 **21.8 s**（事件解码占绝大部分）。
- 同一个构建顺带产出 `build_timeline/equipment_events.csv` 与
  `player_builds.csv`：按 `player+equip_id` 首次出现去重，价格取事件里的
  `price`，装备名留空（不在仓库内保存游戏文本）。161129 局产出 547 条购买、
  163751 局 627 条。
- 前端组件 `web/v2-timeline.js` 已存在并接在回放详情页；`null` 渲染为"—"，
  不需要为 Tier 0 单独改页面。
- 仍未做：检查点补传后不会自动重建时间轴（需重跑构建）；装备名称/图标
  依赖 `resources/catalog`，没有目录时显示 ID。

### 检查点补传 → 自动重建（Tier 2 闭环）

`POST /api/replays/{id}/checkpoints` 成功后启动后台重建：读取该局 `.abc` 字节流
与已存检查点行（只取 `gold`/`kills` 非空的行），按 `entity_id → 玩家名 →
英雄|阵营` 三级键匹配，重写 `data/v2/<sha>/`。

实测（服务端，非离线脚本）：导入 161129 → 补传 `state.jsonl`（3,043 行）→
**22.6 s** 后 `meta.tier` 从 `events-only` 变为 `events+checkpoints`，
`entity 538 / 94 s` 读到 gold 1083、level 3、kills 2。

同期发现并修复一个前端缺陷：聚合团队经济时把 `gold == null` 当成 0，
导致 Tier 2 的稀疏检查点被画成从 0 起的尖刺。现在只有非空值入图；点数
少于 20 时改画散点并标注“仅检查点 · 未连线”。

浏览器验收（Playwright headless，1440×1000）：`#replays` 列表 2 个回放，
点开 161129 后 `.v2d` 渲染成功，显示“7.0k 行 / 10 人 / 1 Hz”、检查点
01:34/02:45/05:00/07:46、经济图 10 个散点。
