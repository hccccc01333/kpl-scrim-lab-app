## 产品体验修订（2026-11-04）

- 桌面顶部采用两行：主导航与搜索一行，功能切换与导入/项目工具一行。对象详情保留面包屑；功能首页以当前功能标签定位，减少重复路径占高。小屏保留可横滑菜单。
- 手机宽度（≤640px）顶栏让位给一级导航：搜索框与「排除验证数据」收起，项目工具收成「⋯」图标，只留「＋ 导入比赛」；`#navigation` 保持横向滚动。此前搜索 120px + 操作区 256px（flex:none）会把导航压到 0 宽并让整页横向溢出。宽表格在 `.db-table-scroll` 内横滑，逐局柱图 ≤640px 在卡片内横滑，`.db-two` 与 `.pf-team-row` 的移动端断点用 `minmax(0,1fr)` / 可换行弹性行，避免 min-content 撑破页面。

- 顶部按首页、数据、绑定、比赛、战队、选手、英雄、BP、对比九组，保留所有深链；首页是赛训产品入口，用真实最近一局、比赛列表与问题入口建立产品体验。数据组只放采集，绑定组只写身份，分析页只读；深度分析以单条页（`#depth/<id>`）按主题挂到比赛 / 战队 / 选手 / 英雄 / BP / 对比的子页签行，不再设「全部分析」索引页（与各模块页签 100% 重复，裸 `#depth` 跳回团队复盘）。
- 视觉采用深墨蓝重点区、暖白内容区与蓝色交互色；统一字号、间距和边框，减少渐变、漂浮阴影和重复说明。
- 主路径：首页 → 比赛档案 → 单局 → 选手 / 英雄详情 → 对比。导入路径：采集页直接创建一局 → 关联素材 → 校对审核 → 保存 → 比赛档案。
- 页面提供可点击面包屑；详情提供页内分段导航。备份、恢复和刷新收进项目工具，不挤占主要动作。
- 首页和详情只使用真实来源数据；经济摘要标记观测时间和采样范围，未知阵营、未绑定身份、缺失值都显式标注。

- 顶部不展示 K 图标或“训练室”品牌标识；导航菜单通过独立展开按钮操作，避免悬停遮挡内容。

## 视觉令牌

- 底色 `#f7f8fa`，白卡，主文字 `#17233b`，次要 `#657187`，线 `#e3e8f1`。
- 强调色 `#2f6fe4`，深强调 `#1f56c4`，浅强调 `#eaf1ff`；警示 `#b26a1f`；正负结果用绿/红语义色。
- 卡片圆角 12px，重点比赛卡 16px，按钮 7px；常规面板使用细边框和极轻阴影。
- 字体 `Inter, Segoe UI, PingFang SC, Microsoft YaHei`；正文 14px，表格 13px，页面标题 32px，移动端 27px，区块标题 18px；数字使用等宽和 `tabular-nums`。

## 页面模板

1. 页头：`page-eyebrow`（英文/中文小标签）→ H1（一个问题或对象名）→ 一句口径说明 → `page-facts` 事实标签 → 右侧一个主动作。
2. 首屏给结论或下一步：样本/状态、卡片或摘要，不先摊配置。
3. 明细分层：主卡片 → 折叠的表格/样本/高级设置；筛选默认折叠。
4. 每个数据块写清口径、来源和样本数；没有字段时显示空态，不伪造。
5. 详情页：KPI 六格 → 走势图/雷达 → 搭档/英雄池 → 最近比赛 → 下一步。

## 数据诚实规则

- 胜率、KDA、分均等数字同时标出样本数；测试库只有一局也照常展示，不用“样本不足”替换功能。
- 只有后端算法的最低门槛（如置换对比至少 4 场）可以不给结果，并说明所需/可用样本。
- BP、装备、资源、分阶段时间轴是条件字段：有则显示，没有则空态。
- 未知胜负不当失利；截图候选不混入正式统计；表格导入先落盘，审核后才入正式比赛。

## 静态资源与缓存口径

- `server.py` 的中间件对 `/assets` 与 `/`、`/analysis` 统一返回 `Cache-Control: no-cache`，静态文件自带 ETag / Last-Modified。改完 `web/` 下的 JS/CSS 后浏览器 F5 会重新协商拿到新内容，**不需要**为了生效去连锁 bump `studio.html → studio.js → 子模块` 三层 `?v=`。
- 现存 `?v=` 只是历史保险（面向离线静态包、中间代理缓存等没有该中间件的场景），保持原样即可，不再作为每次改动的必做步骤；但新增模块引用时要带上版本号，和其它引用保持一致。唯一例外：导出成不跑 `server.py` 的静态包时，才需要统一 bump 或改用内容哈希。
- 判断有没有拿到新版，用浏览器实际渲染结果验证（如新增 DOM class 是否出现），不要只凭 `?v=` 推断。

## 深度分析单条页的口径

- 各模块子页签的深度分析单条页直接读 `data/camp_details/`（营地十人面板）与 `data/official_replays/`（官方回放同步），与「比赛档案」基于 `training.sqlite3` 的正式比赛记录**不是同一批数据**，也不接受顶栏的日期、对手、来源、「排除验证数据」等筛选。
- 页头必须写明「营地口径，不随顶栏筛选变化」；单条分析另写目的、样本与诚实边界。不要把两套样本混说成「N 场比赛」。
- 分边视角：可分边的分析带「视角」选项框（全部 / 我方 / 对方 / 对比 + 已命名的对手战队），由 `?side=own|opp&team=` 驱动后端过滤；我方阵营默认按营地取数账号 `head.acntCamp` 自动识别，教练在「对局分边」页可覆盖并给对手命名（存 `match_meta` 的 `camp:<gameSeq>` 覆盖层，改动会令深度 facts 缓存失效）。双边过程图（逐局节奏 / 经济差 / 事件密度 / 击杀节奏）与蓝红视角体检 `sided=false`，不出选项框。
- 分路显示中文路名：营地 `position` 编码 0=对抗路 / 1=中路 / 2=发育路 / 3=打野 / 4=游走（与 `bp_camp.POSITION_LANES` 同源，已按本批高频英雄核对），不再显示原始编码「分路 0–4」。

## 分析可视化重构（2026-11-04）

- 表现探索：分均经济/输出等指标散点图，点选检查对象、样本量和详情；可切换带原值的列内分位热力矩阵。
