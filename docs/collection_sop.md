# 每局采集说明与示例

2026-11-04 首版（2026-11-11 口径更新）。王者营地只保留约一个月对局详情，采集因此有两条路：
**① 营地路径（窗口内）**：唯一必采是本局王者营地网页回放链接；审核门槛二选一：营地自动同步导入十人面板（推荐主路径），或同局七张赛后截图 + 一段完整录屏（传统兜底）。
**② OCR 新录入（窗口外）**：超过一个月、营地没有详情的老局，不需要营地链接；在截图 OCR / 录屏 OCR 页从一组七页截图或一段完整录屏报告直接「新建一局并录入」，七页截图齐全或十人阵容完整的录屏报告任一即可审核保存。
已有通道只是缺素材时用「补采到已有对局」，与新录入一局不是一回事。标准表格与 `.abc/.ope` 回放文件始终选填。

[打开含示例的采集规范](http://127.0.0.1:8766/assets/collection-guide.html) · [建立本局](http://127.0.0.1:8766/#capture)

## 王者营地链接怎么取得（唯一必采）

**最快的一条**：在营地 APP 里打开这一局的战绩详情，点「分享」转发到微信，在微信里
复制那条 `cu.qq.com/...` 短链，直接粘进本局。短链会 302 一跳落到公开的营地页面，
参数齐全，不需要登录，也不用在小程序里反复找入口。

**一批一起收**：选手把当天的分享都发进群后，到工作台「采集通道」页的
「批量导入营地分享链接」一次粘贴（最多 20 条）。每条自动展开、去重，显示对局编号、
模式、胜方、时长和团队金币；点「创建本局」即建好通道并关联营地来源。失败条目单独
标红，不影响其余。模式值目前只实测过 `battleType=16`（排位）；训练赛（征召开房间）
的取值待积累，出现未知数字时不要猜，以通道内的核对为准。

手动找链接的步骤（没有分享按钮时）：

1. 用本局游戏账号登录王者营地，在“战绩”中找到对应日期、英雄、比分的比赛。
2. 进入该局详情，再打开“对局回顾 / 复盘”。
3. 在回顾页的“分享 / 更多”中查找“复制链接”或“在浏览器打开”；如果能打开浏览器，复制地址栏里的完整网页网址。具体菜单名可能随营地版本变化。
4. 在本局“王者营地链接”中粘贴，点击“提取并关联”，核对返回的比赛信息。只有成功关联才算完成，不能只粘贴后离开。

格式示意，以下占位符不能直接提取：

```text
https://camp.qq.com/h5/webdist/battle-replay/index.html?gameseq=对局编号&gamesvrentity=服务器编号&relaysvrentity=转播编号&playerid=玩家编号
```

保持分享时的全部参数，不手动拼写；个人回放须保留四个参数。营地首页、短视频、只有截图都不能替代回放链接。
`#小程序://王者营地/xxx` 这种纯文本卡片还原不了参数，要改发能复制的 `cu.qq.com` 短链；
若当前客户端没有任何复制入口，先保存草稿，向采集负责人索取本局链接。

## 一段录屏从哪里开始、到哪里结束（营地兜底 / OCR 新录入都适用）

- 开始：进入回放前就开始录屏，包含双方十人英雄/昵称加载页，清楚停留约 5 秒，并完整录到局内 00:00。
- 过程：原始横屏比例、简体中文，建议 1080p、30 fps、1 倍速，全局连续；不裁切顶部时钟、比分与双方团队金币，不剪辑、不拖进度跳过过程。
- 必须打开：显示双方各五人的 K/D/A 和累计金币的团队面板，尽量全程可见。单英雄技能/属性面板、英雄可用金币不能替代团队累计经济。
- 补充打开：约 00:30、之后每 5 分钟、结束前有条件时打开完整十人记分板，显示昵称、KDA、累计金币，停留至少 5 秒，再关闭继续播放。不要长时间遮住主要 HUD。
- 结束：录过水晶结束、胜利/失败动画，进入本局赛后战绩页停留约 5 秒后停止。七张截图另存，不用一段视频代替七张结算图。
- 提交：在“录屏采集”上传一个 mp4/mov/mkv/webm，单文件不超过 2 GB。识别完成后导出一份 JSON，在本局关联。每局一份录屏报告即可；一份报告不自动证明拍摄完整，复核人仍要检查起止和遮挡。

真实加载页、团队面板与结束画面示例和上传入口见[录屏规范](http://127.0.0.1:8766/assets/collection-guide.html?section=video)。只读取实际可见画面；16:9 / 20:9 已有适配，界面改版或遮挡可能需要人工核对。

## 七张赛后结算图（营地兜底 / OCR 新录入都适用）

同一局，每种各一张：

1. 战绩·装备型：比分、胜负、时长、十人 KDA 与装备。
2. 战绩·KDA 占比型：击杀、死亡、助攻及占比。
3. 数据：输出、承伤、经济、参团率。
4. 输出：伤害与伤害转化。
5. 生存：承受伤害与每死承伤。
6. 发育：金币、野怪经济、补刀。
7. 团队：参团、控制、治疗、对塔。

六个页签中，“战绩”有两种显示方式，合计七张。保留顶部比分、双方十人、列名和底部页签；原图上传，不裁切、拼图或盖住字段。文件可命名为 `01-战绩装备.png` 到 `07-团队.png`。七张同类图不能凑齐，数量和页型都检查。真实同局截图见[七张清单](http://127.0.0.1:8766/assets/collection-guide.html?section=screenshots)；示例保留真实数值，仅在教学页面用遮罩隐藏昵称。

## 标准表格（选填）

使用[Excel 模板](http://127.0.0.1:8766/assets/capture-guide/match-template.xlsx)、[空白 CSV](http://127.0.0.1:8766/assets/capture-guide/match-template.csv)或[虚构示例 CSV](http://127.0.0.1:8766/assets/capture-guide/match-example.csv)。想先跑通导入流程，用[十人一局示例](http://127.0.0.1:8766/assets/capture-guide/match-sample.csv)：它填好了一整局十人数据，可直接上传；导入后只在「数据范围 → 表格导入」勾选时出现，正式记录不要用它。Excel 第一张是填写模板，第二张是虚构示例，第三张为字段说明；上传只读取第一张。

保留所有表头，一局十行、每行一人，blue/red 各五行，每方五个分路各一人，`本队阵营` 十行都写本队在 blue 还是 red；不增加标题行、合计行、合并单元格。多局就往下追加，每局十行、对局ID不同。对局ID、日期、本队阵营、阵营、分路、选手、英雄的值必填；对手和数值未知可留空，不用零冒充缺失值。同一局内日期、对手、时长保持一致。不能混入场均或赛季汇总。示例编号会被拒绝，必须替换成真实记录。

计数/经济/伤害用非负整数原值，不写 `1.2万` 或 `12k`；参团率 62.5 表示 62.5%，不要填 0.625；评分 0–100，时长用 1–7200 秒。表格只抄**王者营地赛后数据**（KDA、经济、输出、承伤、参团率、评分、时长、胜负），不要求回放数据。完整字段规则见[Excel 模板](http://127.0.0.1:8766/assets/capture-guide/match-template.xlsx)的第二、三张工作表。表格和截图冲突时保留冲突，必须人工核对。

## 校对与保存

先确定这一局走哪条路：营地拿得到的局，在「采集 → 营地同步」里拉取并同步；营地拿不到的老局，在「截图 OCR / 录屏 OCR」里点「新建一局并录入」建档。已有通道只是缺素材时，用同一页的「补采到已有对局」把截图 / 录屏挂到那局。

审核口径按录入方式区分：营地通道要关联营地回放链接（唯一必采）并导入营地十人面板，或补齐七张截图与一份录屏报告（二选一）；OCR 新录入通道不要求营地链接，七张截图或一段十人阵容完整的录屏报告任一即可。检查日期、比分、十人身份、英雄和阵营，保存草稿修订，填写复核人并审核保存。审核门槛未满足时页面列出缺项，服务端也拒绝绕过审核或直接保存。表格与回放文件为空不阻止审核。

原有已保存记录保留可读；旧草稿再次审核或保存时遵守当前必采要求。备份在“项目工具”；原始录屏和营地目录的备份范围见[平台说明](unified_platform.md)。

## BP 补录与多局表

通道的 BP 面板可记录左右双方禁用和选用、一手方与备注；已保存的对局在比赛详情中点击“BP 补录”，单独保存即可。未知手序留空位，不把第五手压缩成第一手。不允许禁用与选用同一英雄，也不允许同类序列中重复英雄。

批量导入页在上传前给出字段与下载链接。推荐每局十行的逐人明细，多局追加到同一张表，使用不同对局 ID；第一行表头，不混入合计。兼容已有表格时先预览并核对列映射、单位和粒度；聚合表无法还原逐局阵容、BP 或过程。单局附件仍遵守上述严格十人模板约束。
