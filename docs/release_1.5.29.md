# v1.5.29 版本说明

> 发布日期：2026-11-10 · 适用：赛训组教练、数据分析
> 从上个正式发布版（v1.5.15）到本版，工作台补上了三块：**单局复盘看得懂、跨局分析按赛训组口径、数据缺口能自己填**。

## 一句话

以前是「数据都在，但要自己拼」；现在每一页都给一句人话结论，点得开证据，缺的数能当场补。

## 一、单局复盘：一局拆成四个页签

单局页原来是 8000 多像素的一条长链，现在按「看什么」拆开，地址带页签，刷新和分享都停在原页：

| 页签 | 里面有什么 |
| :-- | :-- |
| **复盘** | 本局结论、BP、阶段对比、比赛脉搏、关键节点 |
| **十人数据** | 十人面板（对位 / 同队）、10 分钟经济补录、中野辅与入侵 |
| **事件** | 团战与掉点、切C 与先手、事件详情 |
| **地图** | 阵线、对位热区、对位纵深 |

### BP 是复盘的第一屏

- **本局 BP 复盘卡**：一句结论（BP 端占优 / 吃亏 / 样本偏薄）+ 两条依据——对位命中（历史同分路同英雄对战，本局有没有兑现）、联动命中（我方组合的历史加成）。
- **联动组合**：每对搭档一张卡，头像 + 组合名 + `2 局 2 胜 · 搭档加成 +27 点`（「协同 pp」改成教练话术，公式在悬停里）。
- **对位压制**：五路各一张卡，写清「**我方占优 / 我方吃亏 / 打平 / 待积累 2/3**」，并给出历史领先率、平均经济差、本局实际对位经济差是否与历史同向。
- 判定口径：样本满 3 局才判，且**领先率与平均经济差必须同向**——只按胜率会出现「标着压制、经济差却是 -954」。

### 分路指标：每个位置只看自己该看的

| 位置 | 指标 |
| :-- | :-- |
| 对抗路 | 分均经济（680/700/740 评级）、经济转输出、承伤、对塔伤害、切C、死亡、参团 |
| 打野 | 分均经济（700/750/800）、野怪经济、输出、切C、入侵、死亡、参团 |
| 中路 | 分均经济、经济转输出、输出、跑图、控制时长、死亡、参团 |
| 发育路 | 分均经济、经济转输出、输出、打团存活、死亡、发育、参团 |
| 游走 | 参团、控制时长、治疗量、每死承伤、承伤、死亡 |

死亡 >2 标红预警；分均经济带及格 / 良好 / 优秀徽章。

### 营地派生卡片（原来没被读过的那批数据）

营地面板的 `dataBehaviorV2` 一直在下发三组卡片，之前没有任何代码读它。现在每个位置先亮一张最相关的，其余收进折叠区：

- 游走 → **视野价值**（如 32 : 24）
- 中单 / 发育路 → **经济转有效伤害**（判断无效输出）
- 打野 → **反野总经济**（如 936）
- 对抗路 → **对位经济差**（如 3415）
- 展开还有：勾中敌方英雄（钟馗 16 次）、控制时长、参与控龙次数、带球总经济……

口径：营地只给一个数、没有分母，所以只做同局参考，**不重算、不插值、不评级**；这一局没下发就显示「—」并说明原因。

## 二、10 分钟经济：营地没有，但可以自己填

教练的整套评估锚在 10 分钟（6800 / 7000 / 7400）。查过三个数据源，都不提供逐人金币时间轴：

| 来源 | 有什么 | 缺什么 |
| :-- | :-- | :-- |
| 营地十人面板 | 终局经济、分均经济 | 没有时间轴 |
| 官方回放 | 团队金币 30 秒一点 | 只有团队，没有逐人 |
| 回放金币流水 | 逐人事件流 | 对不上账（残差 17.5%，个别 43%） |

所以在「十人数据」页签加了一张补录卡：

- 我方 5 + 对手 5，共 10 格，**失焦即存**
- 存进覆盖层，不动原始数据包，随时可改
- 填完立刻出评级：对抗路 / 发育路 **6800 及格、7000 良好、7400 优秀**；打野 / 中路 / 游走只显示数值（口径不同，不混套）
- **不填就留空，不估、不补**

## 三、跨局分析：按赛训组的问法分页

- **拆成五个页签**：这段时间 / BP 与阵容 / 五路与人 / 资源与团战 / 对手，页签写进地址（`#cross/bp`）
- **删掉上万像素的逐局对照台**：跨局页只留结论卡；要看那几局，点卡底的「看这 N 局」，卡内展开一行一局，点行进复盘，还能导出 CSV
- **新增账本**：英雄账本（我方选过的英雄：局数、胜算，按出场 / 按胜率两个视图）、对手账本（按对手名分组：胜负、10 分钟经济差、时长）
- **阶段口径锁死**：0–4 对线 / 4–10 发育 / 10 分钟后，全站共用一处定义（热区、脉搏、阶段对比、优势归因都是它）；`/api/cross/vectors` 直接带 `at4`、三段净增与原始经济点，不再把 30 秒序列压成 5 分钟一点

## 四、事件与地图：从「有数据」到「看得懂」

- **比赛脉搏点位可点**：龙＝菱形、BUFF＝圆点、防御塔＝方块、水晶＝大方块，金青分阵营；点标记弹小卡，写清时刻、具体资源名（如「0:50 · 红 BUFF · 对手 · 兰陵王」）、谁拿的。
- **塔名有名字**：从营地 H5 的 `getTowerRoad / getTowerIndex` 还原「阵营 + 路 + 塔序」，能写「对方中路高地塔」。
- **资源控制**：控制率做成主数字 + 进度条，四个目标各一条对向条，防御塔拆到一塔 / 二塔 / 高地塔 / 水晶。
- **切C 与先手**：五张统计卡（切C / 先手 / 击杀，并写清切了谁），逐条账本收进折叠区；每行标「我方 / 对方」，杜绝「自己人杀自己人」的误读。
- **对位热区**：径向糊光斑换成**离散分格**（每格按停留时长分 5 档），补上「对线期 0–4 / 发育期 4–10 / 后期 10+」三个快捷键。
- **打野并线**：三段 × 三路可视化，双人 / 三人分列；组里必须有打野（射手+辅助不算），10 分钟后折算成「次/10 分钟」。实测 23 局均值：打野 10.7 次，一起吃线最多的是中路 6.4、对抗路 4.1。

## 五、采集：一条营地链接就够

- 营地同步完成后**自动补拉官方回放**并挂到通道——以前这一步要教练逐局再贴一次链接，前端从未调用过 `/api/official/replay`，链路一直是断的。
- 新增覆盖面盘点与一键补齐：`GET /api/official/coverage`、`POST /api/official/backfill`。本机实测 32 条通道里 22 条有回放，一键补到 23。
- **营地载荷全量归档**：逐局 `fields.json`（路径 / 类型 / 次数 / 示例）+ 跨局索引 + H5 前端文案，`GET /api/official/archive` 可查。营地改版后能直接 diff 出新增字段。
