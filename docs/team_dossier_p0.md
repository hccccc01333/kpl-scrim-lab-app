## 1. 基础一：五路英雄分类标准

> **权威来源（2026-11-15 赛训组更新）**：《王者荣耀_KPL赛训英雄标签_五路12类精简版_2026-11.xlsx》，含 133 英雄标签表（13 字段）、英雄分路候选（176 条）、五路 12 类类型词典、19 维 0/1 能力矩阵、逐局数据录入模板；英雄 ID 对齐仓库 `resources/catalog.json`。
> **对账结果（2026-11-15）**：133 英雄全部收录；默认类型变化 52 处、副分路登记 43 条；槽位级「待分类」由 374 局 / 31 组合降至 106 局 / 16 组合；新增英雄元流之子(射手)。**以工作簿为准**，导入仓库是本文 P0-1 的实施任务。

### 1.1 主类型词表（五路 12 类精简版，2026-11-15）

> 2026-11-15 赛训组更新为「五路 12 类精简版」：默认层与本局层共用同一套词表。旧细分（法系边、刺客野/战士野/法系野、工具人法师/法刺/炮台/阵地/爆发/推进、功能射手）已收编；以下按新表执行。

| 分路 | 主类型 | 英雄数 | 说明 |
| --- | --- | --- | --- |
| 对抗路 | 战边 / 坦边 | 27 / 10 | 法系输出边统一归战边；带线、支援为能力标签，不单列类型 |
| 打野 | 刺野 / 战野 / 坦野 | 15 / 9 / 1 | 法刺野/部分爆发射手野并入刺野；蓝领/野核是本局资源职责，不是主类 |
| 中路 | 工具人 / 法核 | 14 / 16 | 法刺/炮台/阵地/爆发/推进统一并入法核；工具人不是「低伤害」同义词 |
| 发育路 | 游射 / 呆射 | 12 / 8 | 按是否有主动位移分组；功能/法伤为细标签 |
| 游走 | 开团辅 / 保护辅 / 功能辅 | 7 / 9 / 5 | 可兼其他职责，按本局主责选一个 |

口径：

- 类型仍按**该局实际分路**取；未收录或分路未登记归「待分类」，不计入类型占比分母；
- 法系边并入战边；刺客野/战士野改名为刺野/战野；工具人法师改名为工具人；
- 不再保留功能边/蓝领野/节奏辅/法伤射手等默认角色型；它们只作为本局职责或能力标签描述。

### 1.2 第二层：能力标签（非互斥）

权威表 = 工作簿「能力矩阵_0-1」：**19 维 0/1 标签**（前排、承伤、开团、反开、保护、控制、爆发、持续输出、消耗、机动、切入、清线、带线、续航、推进、支援、入侵、收割、团队增益），133 英雄全覆盖。

`hero_roles.py` 九维到 19 维的映射（迁移期兼容，九维最终退役）：

| hero_roles 九维 | 19 维对应 |
| --- | --- |
| engage 强开 | 开团 |
| peel 保护/反开 | 保护 + 反开（拆为两维） |
| burst 爆发 / sustained 持续输出 | 爆发 / 持续输出（同名） |
| frontline 前排 | 前排 + 承伤 |
| waveclear 清线 | 清线 |
| roam 游走/支援 | 支援 + 机动 |
| macro 推塔/控龙/运营 | 推进（控龙、运营无对应，随九维退役） |
| resilience 容错/反打 | 反开（部分覆盖，随九维退役） |

**战术功能标签由 19 维规则派生**（后端唯一实现）：双前排 = 前排 ≥ 2；强开团 = 开团 ≥ 2；保护链 = 保护 + 反开 ≥ 2；清线转线 = 清线 ≥ 3；无前排 = 前排 = 0（负面标签，供体系短板展示）。
**「双核」不由能力标签派生**：工作簿明确「野核/法核/射核属于资源/输出职责，需经济与输出占比判断」——双核/单核一律用十人面板资源数据计算；无面板的局不给该标签，不降级为能力猜测。

### 1.3 判定优先级与「待分类」

分类取值优先级（高→低）：

1. 人工修正层（未来 overrides 表，带版本窗口；当前为空）；
2. 英雄-分路类型表 × 该局营地记录的**实际分路**（工作簿「英雄分路候选」：默认建议 133 条 + 副分路候选 43 条）；
3. 仅当该局分路缺失时，回退英雄默认分路。

对齐细则：

- 副分路候选 43 条中仅 9 条给出具体类型（廉颇游走=开团辅、夏侯惇打野=坦野、项羽游走=开团辅等），其余 34 条标「待按实际分路及版本确认」——后者**不入表**，实际对局出现时落「待分类」，与现行「实际分路未登记→其他」逻辑一致，不猜；
- 工作簿「分类置信度」：高 103 / 中 24 / 待复核 6（蚩奼、元流之子系列、空空儿等较新英雄）；「待复核」不阻塞统计，页面标注置信度；
- 仓库「其他」更名为**「待分类」**：对应工作簿的「射手待细分」「待按实际分路及版本确认」等占位词，统计口径统一显示「待分类」。

硬规则：

- 「待分类」不计入任何类型占比的分母，且**必须单独计数展示**，不得静默消失；
- 含待分类路的局仍计入有效场次，但其类型签名中该路记 `待分类`，对应组合进入「含待分类」行（§2.5）；
- 「待分类」不被视作成功识别——验收口径（§5）以覆盖率检查保证。

### 1.4 版本化（治理字段随导入生效）

工作簿已携带 `版本范围 / 分类置信度 / 赛事核验状态 / 复核说明 / 官方目录来源` 五个治理字段，随 P0-1 一并入库；当前「版本范围 = 按比赛版本核验」即全部标签待逐局核验，语义上等价于「单版本周期有效」。对局数据 version 字段（0/396）开始填充后启用版本窗口，启用前所有分类对全部局生效；接入 KPL 历史数据时必须启用。

### 1.5 缺口状态（原「立即缺口」已解除）

- 选用/禁用覆盖率：**100%**（130/130，工作簿 133 全覆盖）；
- 仓库缺口英雄已由工作簿补齐：雅典娜 → 战野（复核说明注明「旧分类『其他』应修正」）、云中君 → 刺野；
- 剩余工作从「补表」变为「导入与迁移」：56 处默认类型变化 + 10 处默认分路变化（曜、诸葛亮、墨子改默认分路，橘右京、蚩奼、苏烈、梦奇、猪八戒、盘古、影等默认分路调整为对抗路）按工作簿为准，导入时生成对账清单备查。

## 2. 基础二：阵容组合统计规则

### 2.1 三层阵容标识

| 层级 | 定义 | 用途 |
| --- | --- | --- |
| 五路类型签名 | 每局每队一条，按固定分路序（对抗→打野→中路→发育→游走）取 5 个主类型 | **主统计层**：使用率、胜率、跨局复用 |
| 战术功能标签 | 由 §1.2 规则从能力标签派生，一局可有多个 | 体系相似性、短板识别 |
| 具体英雄阵容 | 分路归位后的 5 英雄 | 下钻证据层 |

一局一队只有一条类型签名；功能标签可有多个。英雄阵容可能每局都不同，但类型签名相同的局归入同一体系。

### 2.2 分母口径（每个指标必须有明确分母）

| 指标 | 分子 | 分母 | 当前数据基础 |
| --- | --- | --- | --- |
| 有效场次 N_eff | — | 该队 BP 名单完整、五路可识别的局 | 396/396 全量 |
| 体系使用率 | 该签名使用局数（每局每队 ≤ 1） | N_eff | 全量 |
| 体系胜率 | 该签名胜场 | 该签名中结果已知的局 | 全量 |
| 双人/三人组合使用率与胜率 | 该组合出现局数 / 胜场 | 对应位置均可识别且结果已知的局 | 全量 |
| 英雄阵容复用 | 相同 5 英雄出现局数 / 胜场 | N_eff | 全量 |
| 按体系的资源类指标（经济/输出/承伤占比等） | 体系局内面板汇总 | **有十人面板的体系局**（102/396） | 子集，页面必须标注「含面板的 X 局」 |
| 红蓝方拆分 | 各阵营子集 | 同上口径按阵营拆分 | 全量（ownCamp 已具备） |

统一硬规则：

- 去重键 **(match_id, team_id)**：阵容类型使用率的分母按「五路类型可识别的有效对局数」计，同一局同一队只计一次（工作簿「使用说明」同口径）；
- 统计所用类型层：P0 组合统计一律用「默认赛训类型 × 实际分路」生成的签名（§1.1 默认层）；「本局类型 / 本局职责」层随逐局录入（§2.6）积累后作为第二口径启用，两者不混算；
- 每局每队每路一个主类型：示例局出现「开团／保护辅」类双类型时，入库取主类型、另一类型进兼容定位，不双计（§8-3）；
- 涉及「待分类」路的组合不计入该组合的分子分母（同局其余可识别位置对正常累计）；签名含「待分类」的局进 unknownRow；
- 资源占比差异**不等于**效率差异：坦野/战野/工具人的资源占比低是职责使然，页面不自动判优劣（延续 `docs/team_page_v2.md` §3 文案规则）；
- 同一统计口径在战队画像、体系表现、组合明细三处复用同一后端实现，禁止前端各自计算。

### 2.3 组合家族

双人（五个预置位置对）：边野（对抗×打野）、中野（打野×中路）、射辅（发育×游走）、中辅（中路×游走）、野辅（打野×游走）。三人（五个预置三角）：中野辅、边野辅、中射辅、野射辅、边中野。另支持教练自定义位置组合（任意 2–4 个分路的笛卡尔视图），不为所有组合单设模块。

每个家族均可切换**位置类型层**（主统计）与**具体英雄层**（下钻）；点击任一组合展开：实际英雄、对应选手、对手、胜负与单局复盘入口（三级下钻原则）。

### 2.4 展示分层与区间（硬规则）

| 条件 | 页面允许的行为 |
| --- | --- |
| 该队 N_eff ≤ 2 | 只显示单局阵容、英雄、客观数据；不给任何胜率、不给体系结论（**当前 104 队中的绝大多数处于此档**） |
| 该队 N_eff 3–9 | 展示组合次数与初步分布；胜率仅显示原始胜负计数，不给百分比 |
| 该队 N_eff 10–29 | 胜率 + Wilson 95% 区间一起展示；可进入探索性体系比较 |
| 该队 N_eff ≥ 30 | 体系对比、对抗矩阵稳定格可用（仍受 §3.2 证据等级约束） |

- Wilson 95% 区间：z=1.96；中心 `(p̂ + z²/2n)/(1 + z²/n)`，半宽 `z·√(p̂(1−p̂)/n + z²/4n²)/(1 + z²/n)`。后端唯一实现，输出上下界，前端只渲染。
- 排序默认按**场次降序**（不是胜率），避免 2-0 的组合排最前误导；
- 区间分层是**展示规则**，不是统计显著性判定；任何组合哪怕全队 50 局，自身只用 2 局就不给胜率结论；
- 单局样本队取消「97/100、S 档」式综合评级，改为「本场相对表现」与「证据充分程度」两个独立指标（上游设计稿 §10，与现有 `percentiles` 的呈现方式一并调整）。

- `functions` 仅在五人能力标签全部收录（19 维矩阵）时计算；不足则返回空数组，不猜短板；「双核」不在其中（资源口径，§1.2）；

- `side` 恒含 blue / red（0 局为空桶），阵营未知进 `unknown` 桶；

## 3. 基础三：阵容对抗分析方法

### 3.1 矩阵定义

- 行 = 研究对象的五路类型签名（或单个位置对），列 = 对手签名（或对手位置对）；
- 每格输出：`{n, wins, losses, wr, wilson, baselineDiff, evidenceLevel}`；
- `baselineDiff = 格内胜率 − 该对象在同筛选范围内的整体胜率`，标注两者分母；
- 第一版只做**类型签名层**；功能标签层待能力标签扩展后启用；
- KPL 组合命中（现 I 模块）保留为**职业参照层**，不参与格内胜负计算，不与训练赛样本混算。

### 3.2 证据等级（三档）与文案硬规则

| 等级 | 条件 | 页面呈现 |
| --- | --- | --- |
| 倾向性发现 | n ≥ 10 且 Wilson 区间不跨越基准线 | 可给「该体系对此类对手历史表现更好/更差」的倾向表述 |
| 初步观察 | 3 ≤ n < 10 | 只展示次数、胜负与区间，不写倾向结论 |
| 证据不足 | n < 3 | 显示原始对局列表，不给格内统计 |

文案硬规则：

- 一律表述为「历史关联」，**禁用「克制 / 因果 / 必然」**；样本受队伍实力、版本、对手强度、选边影响，页面固定注释此事；
- 稳定格（n≥10）才允许进入「赛前准备清单」类结论区；
- 缺手序、缺时间轴、缺版本标签时，对应分析显示「无完整手序记录 / 无时间轴数据 / 版本未知」，不造结论（延续现有 `meta.limits` 机制）。

### 3.3 三个视角的启用条件

| 视角 | 数据基础 | 决定 |
| --- | --- | --- |
| 同体系 × 红蓝方 | ownCamp 396/396 具备 | **立即启用**（§2.5 `side` 块） |
| 同体系 × 对手强度 | 对手同池分位（现有 `percentiles`）仅作代理 | 启用，但标注「对手强度为同池分位代理」 |
| 同体系 × 版本 | version 0/396 | **关闭**，接口留位；version 开始填充后自动启用 |

### 3.4 明确禁止

- 不把多个独立训练赛拼接为 BO 序列（session 字段当前为空，无可靠 series_id）；
- 不跨版本混算（当前全窗口本就只有一个版本周期，启用版本化前无此风险，规则先立）；
- 不把 KPL 命中当成本队体系有效性的证据；
- 对手体系不可识别的局，从矩阵分母剔除并计入「含待分类」提示。

## 7. P2 增量契约：体系资源对照与对抗矩阵（2026-11-14 实施）

`team-deep` 的 `lineups` 块新增 `resources` 与 `matchups`（引擎 `lineup_stats.py`，后端唯一实现）。

### 7.1 `lineups.resources`（按体系的资源对照，上游设计 §4.1）

```json
"resources": [{
  "sig": ["战边", "坦野", "法核", "呆射", "开团辅"],
  "games": 12, "panelGames": 12, "wr": 58.3,
  "lanes": {"对抗路": {"goldShare": 21.4, "dmgShare": 18.2, "takenShare": 26.0}, "...": {}},
  "top1Share": 24.6, "towers": 7.8, "dragons": 2.1, "goldDiff": 412.5,
  "gamesRef": ["..."]
}]
```

- 口径：占比按十人面板**已知值**汇总（缺谁不补 0），与逐人卡一致；`panelGames` < `games` 时页面必须标注子集（「含面板 X / 共 Y 局」）；
- 五路占比差异**不等于**效率差异（坦野 / 蓝领职责吃钱少），页面不得自动判优劣；
- `goldDiff` = 被研究战队 − 对手（正 = 被研究方领先）；
- 分阶段表现（0–4 / 4–10 / 10+ 分钟）仍关闭：moneyTrend 0/104 非空，无时间轴数据。

### 7.2 `lineups.matchups`（阵容对抗矩阵，上游设计 §5）

```json
"matchups": {
  "cells": [{
    "row": ["战边", "坦野", "法核", "呆射", "开团辅"], "col": ["坦边", "刺野", "工具人", "游射", "保护辅"],
    "n": 3, "wins": 2, "losses": 1, "wr": 66.7, "wilson": [20.9, 87.9],
    "baseline": 50.0, "baselineDiff": 16.7,
    "evidenceLevel": "initial",
    "side": {"blue": {"games": 2, "wins": 1}, "red": {"games": 1, "wins": 1}},
    "gamesRef": ["..."]
  }],
  "rowBaselines": [{"sig": ["..."], "games": 4, "wins": 2, "losses": 2, "decided": 4, "wr": 50.0, "wilson": [11.0, 89.0]}]
}
```

- `row` = 被研究战队体系，`col` = 对手（我方）体系；格内只计**双方**五路类型均可识别的局；
- `baseline` = row 体系对全体对手的整体胜率（同批对局，见 `rowBaselines`）；`baselineDiff` = 格内胜率 − 基准，仅两侧都 ≥3 结果已知时输出；
- 证据等级三档（§3.2）：`insufficient`（n<3，只给原始记录）→ `initial`（3≤n<10，展示不给倾向结论）→ `established`（n≥10 且 Wilson 区间不跨基准，可写「倾向性发现」）；
- 文案硬规则：只写「历史关联」，禁「克制 / 因果」；版本视角关闭（version 0/396），对手强度代理（同池分位）与位置对粒度随样本积累后续启用。
