## 0. 目标

### 0.0 v5 呈现层（2026-11-16，当前生效，覆盖下文的 v3 / v4 结构）

赛训组复盘会（口头）定下的三条硬约束：**不要横向细条形**、**战队层对照只留说得通的指标**、
**选人模式要按时间窗 × 赛制分析到每一手**。据此整页重做，下文 v3/v4 的段落划分与图表描述仅作历史记录。

**页面结构（六段）**：`01 样本与整体 / 02 BP 手序 / 03 阵容结构 / 04 英雄池 / 05 打法与结构 / 06 对位与关联`。
删掉的段落：领先 / 落后、资源与对位、变化与异常、证据与方法、KPL 职业参照、数据质量与命名维护。

**筛选（作用于下方全部分析段，头部数字始终是全样本）**：

| 维度 | 取值 | 口径 |
|---|---|---|
| 时间窗 | 近 3 / 7 / 30 天、全部、自定义起止 | 以「最近一场」为基准，不是以今天为基准；锚点写在筛选条上 |
| 赛制 | 全部 / BO3 / BO5 / BO7 / 未登记 | 来自 `training_series.best_of`；没有登记的局不并入任何 BO |

**图表语言**（`.tp-page` 内不再出现 4–6px 的横向进度条）：

| 结论 | 图元 | 备注 |
|---|---|---|
| 整体对照 | 镜像密度（上对手 / 下本队）+ 中位虚线 | 只留控龙 / 推塔 / 经济 |
| 逐手 BP | 逐局 × 逐手头像梯阵（每列一局、格底颜色标胜负） | 看「第几手有没有变」 |
| 手序分布 | 手序 × 分路热力格（大格 + 头像）+ 名次表 | 名字下方的「平均第几手」是优先级 |
| 阵容结构 | 核 × 控矩阵、核类型卡、逐局类型梯阵、位置组合卡 | 五路两两组合共 10 组 |
| 英雄池 | 选 / 被 ban / 剩余 三列头像 | 每列 ≥3 个英雄 |
| 经济分工 | 环形占比（两队同尺寸） | 比的是份额不是总量 |
| 输出承伤 | 散点（x 输出份额 / y 承伤份额 / 大小经济） | 标签做防重叠 |
| 分路对位 | 发散热力矩阵（格内是本队相对对手的变化率） | 正数＝本队更高，颜色与符号同向 |
| 条件胜率 | 环形条件卡（一条件一卡，红＝对手更能赢） | 淡显＝样本 <4 局 |
| 倾向漂移 | 斜率小图（BO 或时间切片）+ 分类对照表 | 只读方向，不做显著性 |

**数据契约增量**（`/api/v3/team-deep`）：

- `games[].bo` / `games[].series`：赛制与系列赛登记（`{id, bestOf, gameNo}`），查不到为 `null`，不按局数猜。
- `games[].draft.ordered`：`{own: {ban, pick}, enemy: {ban, pick}}`，每条 `{hero, lane, archetype}`；顺序来源仍由 `orderAssumed` 标注。
- `games[].sides.{own,enemy}.lineup`：`{cores, coreList, controls, front, engage, peel, damage, known, total, tags}`；
  核＝战边 / 刺野 / 战野 / 法核 / 游射 / 呆射，控按 `hero_capabilities` 的「控制」维度计数。
- `coverage`：`{games, boKnown, boCounts, draftKnown, draftVerified, firstSeen, lastSeen}`，供前端标注样本与来源。

**写作规则**：每张卡最多一行口径；「手序来自模板还原」必须写出来；条件关联一律注明不是因果。

## 1. 页面结构（从上到下）

### B. 打法画像（一句话结论）

### D. 资源分配（谁在吃经济）

### E. 团队风格四象限（逐局识别）
- 轴（游戏话）：
  - 横轴：**经济集中在一个人 ←→ 分给多个人**（单核 ↔ 多核）
  - 纵轴：**靠打架建立优势 ←→ 靠兵线/资源/推塔建立优势**（打架 ↔ 运营）
- 四象限命名：
  - 左上 单核进攻：经济集中给一个核心，由核心带动前中期进攻（野核带节奏、围绕核心抓机会）
  - 右上 多点进攻：多个位置有威胁，找不同位置的机会（中野辅联动、战边进场、双核输出）
  - 左下 保核运营：围绕主要输出点发育，靠兵线与资源找接团机会（射核发育、保护后排、关键团接战）
  - 右下 多线牵制：多个位置承担资源与边线任务（双边带线、转线推塔、资源交换）
- 时间窗：最近 7 / 15 / 30 天 + 全部；窗口锚点 = 数据里最新一局日期（页面注明）。
- 每个窗口给：局数、四象限分布（各几局）、平均点位、主要倾向（占比 ≥50% 且 ≥3 局才给结论，否则「样本不足，暂不归类」）。
- 图：对手逐局散点（每局一个点，点大小 = 局时长或固定），可叠加本队点位；悬停显示该局证据。
- **证据卡**：每局列出「支持这一象限的证据 / 还缺什么」：
  - 有：经济第一是谁、经济占比、每分钟击杀+助攻、每分钟推塔+控龙、最终经济差、推塔数、控龙数。
  - 缺：没有时间轴/位置轨迹 → 主动开团、中野辅联动、兵线处理、领先后怎么打**暂不能判断**，一律写「证据不足」。
- 严禁用「比赛时长」代表后期倾向、用「击杀多」直接说进攻强。

### F. 体系表现（怎么打更容易赢）

### 2.3 风格计算（后端唯一实现，`team_style.py`）

所有队伍、逐局统一用这一套；前端不得另算。

1. **经济集中度（多核程度）**
   - `top1Share = max(gold) / sum(gold) * 100`（每队每局）
   - 同池分位 `top1 = [q33, q66]`（池 = 数据内所有队伍 × 每局，双向都算，去重按「队-局」）
   - `x = clamp(100 * (q66 - top1Share) / (q66 - q33), 0, 100)`：x 越大越偏多核；x 越小越偏单核。
2. **节奏倾向（打架/运营代理）**
   - 每队每局：`fightPerMin = (kills + assists) / minutes`
   - `macroPerMin = (towers + 0.7 * dragons) / minutes`（dragons = 5 个龙字段之和）
   - 同池分别取 `fightPerMin`、`macroPerMin` 的百分位排名 `pf`、`pm`（0–100，池 = 数据内所有「队-局」的两个方向）
   - `y = clamp(50 + (pf - pm) / 2, 0, 100)`：y 越大越偏打架，越小越偏运营；两项都高或都低时落在 50 附近（均衡），不会被单项拉满。
   - 缺 minutes / 击杀助攻 / 推塔控龙 → `y = null`（证据不足）。
   - 注意：这是终局面板代理，不能区分「主动开团」与「被迫接团」；页面必须标注「代理」。
3. **象限**
   - `x < 50 且 y >= 50` → 单核进攻；`x >= 50 且 y >= 50` → 多点进攻
   - `x < 50 且 y < 50` → 保核运营；`x >= 50 且 y < 50` → 多线牵制
   - x 或 y 为 null → 象限 null（证据不足）
4. **窗口**
   - 日期解析兼容 `MM-DD HH:MM` 与 `YYYY-MM-DD ...`；无年份按数据内最近年份补，跨年时取不晚于锚点的最近一年。
   - 锚点 = 该队最近一局日期（不是今天）；窗口 = `锚点 - (N-1) 天 <= day <= 锚点`。
   - `sufficient = games >= 3`；`quadrant` 仅当 `sufficient` 且该象限占比 >= 50% 才给，否则 null 并给 `share`（最大象限占比）。
5. **证据**
   - `evidence`：经济第一（路/占比）、每分钟击杀+助攻、每分钟推塔+控龙、推塔数、控龙数、最终经济差。
   - `missing`：固定三条（时间轴/位置轨迹、禁选顺序、分路口径）。
