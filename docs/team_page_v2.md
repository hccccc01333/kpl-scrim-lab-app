# 战队页 v2 · 整合设计 + 数据契约

状态：实施中（2026-11-13）。本文是后端、前端、QA 共同遵守的契约；字段名以本文为准，改契约先改本文。

## 0. 目标

把「战队档案 · 详情」从「信息页 + 分析页」两层结构改成**一个整合页**：

- 顶部先给教练能一眼读懂的「信息 + 打法画像」；
- 往下是五段分析：喜欢什么 → 资源分配 → 团队风格四象限 → 体系表现 → 分路对位 → BP 偏好 → 阵容组合；
- 删掉重复/不可靠的分析：交手走势、节奏与终结、赛前洞察、旧「经济投入 × 输出转化」四象限、独立英雄池（并入「喜欢什么」）；
- 不再使用「基础层 / 中级层 / 高级层」的套层结构；
- 统计术语换成游戏术语（禁 pp、HHI、分位、p 值等），说不清的就写「证据不足」。

## 1. 页面结构（从上到下）

### A. 头部信息（信息）
- 队名、命名/教练状态、首次/最近交手、本队战绩（X 胜 Y 负）、对手胜率、场均时长、样本徽章（<3 局只作参考）。
- 五路选手条（分路 + 选手名 + 局数），数据来自 `team.players`。
- 操作：命名/改名、数据范围、刷新（沿用现有 `data-team-rename` / `data-action`）。
- 右侧「战队得分」小卡：分数 + 档位 + 五项权重说明（怎么算：对手交手胜率 30%、分均经济 20%、KDA 改称「对抗」20%、分均输出 15%、场均推塔 15%；除胜率外用同池分位，缺项按剩余权重归一）。**只解释，不重复画一遍原始数据**。
- 小字「整体数据对照」：对手 vs 本队 6 项有用数据（场均经济、场均击杀、场均推塔、场均控龙、分均输出、分均承伤），左右双向条 + 差距用「多/少」文字，不用 pp。

### B. 打法画像（一句话结论）
- 标题句示例：`偏射核 · 中野辅找节奏 · 团战接战`。
- 三块内容：
  1. **主要经济核心**：五路经济占比条（百分比 = 该路经济 / 全队经济），高亮第一路；副文案「发育路 27% · 队内第一」。
  2. **主要阵容倾向**：两个组合视图，各取前 2：
     - 下路组合：发育路类型 + 游走类型（如「呆射 + 保护辅 44%」）
     - 中野组合：打野类型 + 中路类型（如「刺客野 + 工具人中单 32%」）
  3. **核心观察**：2–3 句，必须由数据支撑并标注证据强弱（见 §3）。
- 明确写「逐局识别，不是永久标签；样本不足只作参考」。

### C. 战队喜欢什么（阵容偏好，按分路筛选）
- 分路筛选 chips：全部 / 对抗路 / 打野 / 中路 / 发育路 / 游走。
- 每个分路：类型占比条（战边/坦边/带线边 等，来自 `hero_archetypes`），以及该类型下的英雄与出场次数。
- 汇总：英雄数、**主力英雄数**（原「有效英雄」= 1/HHI，改成「实际能用的英雄数」）、**英雄池偏科**（原「集中度」HHI，用「不偏科 / 略偏科 / 很偏科」文字档）。
- **不重复显示「选用次数」**（英雄数已隐含）。

### D. 资源分配（谁在吃经济）
- 指标切换：经济 / 输出 / 承伤。
- 分路筛选：全部 / 单路（点某一路高亮）。
- 左右对位：每一路一行，**左 = 对手占比，右 = 本队占比**，中间 0 点；条越长占比越高。
- 文字结论用游戏话：如「对手把 28% 的经济给了打野，本队 22%——对面更靠打野吃钱」；禁止 pp。
- 单核/多核提示：经济第一的人拿了全队 X%（对手）/ Y%（本队），并说明落到四象限的哪一侧。

### E. 团队风格四象限（逐局识别）
- 轴（游戏话）：
  - 横轴：**经济集中在一个人 ←→ 分给多个人**（单核 ↔ 多核）
  - 纵轴：**靠打架建立优势 ←→ 靠兵线/资源/推塔建立优势**（打架 ↔ 运营）
- 四象限命名：
  - 左上 单核进攻：经济集中给一个核心，由核心带动前中期进攻（野核带节奏、围绕核心抓机会）
  - 右上 多点进攻：多个位置有威胁，找不同位置的机会（中野辅联动、战边进场、双核输出）
  - 左下 保核运营：围绕主要输出点发育，靠兵线与资源找接团机会（射核发育、保护后排、关键团接战）
  - 右下 多线牵制：多个位置承担资源与边线任务（双边带线、转线推塔、资源交换）
- 时间窗：最近 7 / 15 / 30 天 + 全部；窗口锚点 = 数据里最新一局日期（页面注明）。
- 每个窗口给：局数、四象限分布（各几局）、平均点位、主要倾向（占比 ≥50% 且 ≥3 局才给结论，否则「样本不足，暂不归类」）。
- 图：对手逐局散点（每局一个点，点大小 = 局时长或固定），可叠加本队点位；悬停显示该局证据。
- **证据卡**：每局列出「支持这一象限的证据 / 还缺什么」：
  - 有：经济第一是谁、经济占比、每分钟击杀+助攻、每分钟推塔+控龙、最终经济差、推塔数、控龙数。
  - 缺：没有时间轴/位置轨迹 → 主动开团、中野辅联动、兵线处理、领先后怎么打**暂不能判断**，一律写「证据不足」。
- 严禁用「比赛时长」代表后期倾向、用「击杀多」直接说进攻强。

### F. 体系表现（怎么打更容易赢）
- 经济转输出：按分路看「经济占比 → 输出占比」，只和同位置/同类型比；写清「吃钱多打伤害少不一定是选手差，可能是坦野/开团职责」。
- 输出/承伤结构：五路输出占比 vs 承伤占比（双向堆叠），说明谁在打伤害、谁在扛。
- 体系胜率：按「打野类型 + 中路类型 + 游走类型」组合分组的场次与胜率；<3 局只显示场次、不给胜率结论。
- 领先/落后：按终局经济差分组，给推塔/控龙/团战数据；注明没有时间轴，只能看终局，不推断「领先后怎么打」。

### G. 分路对位（左右对位 + 分路筛选）
- 每路一张卡：左 = 对手同位置选手，右 = 本队同位置选手；点分路 chips 只看一路。
- **各分路指标（都不含 KDA）**：
  - 对抗路：分均承伤、参团率、场均推塔、分均经济
  - 打野：分均经济、参团率、场均击杀参与（击杀+助攻）、控龙（队伍）
  - 中路：分均输出、分均经济、参团率
  - 发育路：**分均经济（首要）**、分均输出、参团率
  - 游走：分均承伤、参团率、分均控制、分均治疗（**不看经济、不看输出**）
- 差距用「对手多/少」文字，不用 KDA，不用 pp。

### H. BP 偏好（按分路筛选）
- 分路 chips：全部 / 五路。
- 四块：
  1. **常选 / 常禁**（按所选分路过滤，显示次数 + 占该队局数比例）。
  2. **遇到我们时爱 ban 什么**：只统计「对本队」的局，列出对手 ban 榜，并标出「其中 X 个是我们常拿的」（用本队英雄池判断针对度）。
  3. **我们 ban 了之后他们用什么替代**：对「我们 ban 掉的、对面常拿的英雄」，给同一分路/同类型的替代选择及次数。
  4. **A 英雄喜欢搭配谁** / **面对我们什么组合用什么打**：双人组合条件统计（次数、胜率、样本门槛），以及本队常见双人组合下对手的选人与胜负。
- 口径：营地只有终局禁选名单，**没有禁选顺序**，页面注明；不猜手序。

### I. 阵容组合（KPL 命中）
- 对手实际拿过的双人/三人/整套阵容，命中 KPL 组合表的：KPL 场次 n、KPL 胜率、最近年份、代表战队；再给「我们交手时这套的场次与对手胜率」。
- 按交手场次降序；<3 局标注「样本」。
- 数据来源写清：KPL 官方赛事组合表（`data/facts/kpl_combos.json`）。

### J. 页脚折叠：数据质量 + 命名维护（沿用现有内容，合并成一个折叠块）

### 删除
- 交手走势（`data-tm-jump="tm-games"` / `gamesPanel`）
- 节奏与终结（`rhythmPanel`）
- 赛前洞察（`insightPanel`）

### 2.3 风格计算（后端唯一实现，`team_style.py`）

所有队伍、逐局统一用这一套；前端不得另算。

1. **经济集中度（多核程度）**
   - `top1Share = max(gold) / sum(gold) * 100`（每队每局）
   - 同池分位 `top1 = [q33, q66]`（池 = 数据内所有队伍 × 每局，双向都算，去重按「队-局」）
   - `x = clamp(100 * (q66 - top1Share) / (q66 - q33), 0, 100)`：x 越大越偏多核；x 越小越偏单核。
2. **节奏倾向（打架/运营代理）**
   - 每队每局：`fightPerMin = (kills + assists) / minutes`
   - `macroPerMin = (towers + 0.7 * dragons) / minutes`（dragons = 5 个龙字段之和）
   - 同池分别取 `fightPerMin`、`macroPerMin` 的百分位排名 `pf`、`pm`（0–100，池 = 数据内所有「队-局」的两个方向）
   - `y = clamp(50 + (pf - pm) / 2, 0, 100)`：y 越大越偏打架，越小越偏运营；两项都高或都低时落在 50 附近（均衡），不会被单项拉满。
   - 缺 minutes / 击杀助攻 / 推塔控龙 → `y = null`（证据不足）。
   - 注意：这是终局面板代理，不能区分「主动开团」与「被迫接团」；页面必须标注「代理」。
3. **象限**
   - `x < 50 且 y >= 50` → 单核进攻；`x >= 50 且 y >= 50` → 多点进攻
   - `x < 50 且 y < 50` → 保核运营；`x >= 50 且 y < 50` → 多线牵制
   - x 或 y 为 null → 象限 null（证据不足）
4. **窗口**
   - 日期解析兼容 `MM-DD HH:MM` 与 `YYYY-MM-DD ...`；无年份按数据内最近年份补，跨年时取不晚于锚点的最近一年。
   - 锚点 = 该队最近一局日期（不是今天）；窗口 = `锚点 - (N-1) 天 <= day <= 锚点`。
   - `sufficient = games >= 3`；`quadrant` 仅当 `sufficient` 且该象限占比 >= 50% 才给，否则 null 并给 `share`（最大象限占比）。
5. **证据**
   - `evidence`：经济第一（路/占比）、每分钟击杀+助攻、每分钟推塔+控龙、推塔数、控龙数、最终经济差。
   - `missing`：固定三条（时间轴/位置轨迹、禁选顺序、分路口径）。

## 3. 文案规则（硬性）

- 不用统计术语：pp / 百分点 / 分位 / HHI / 协同值 / 显著性 / 归一化。改用：占比、多/少、更爱、偏、吃经济、开团、保人、带线、打团、控龙、推塔、节奏。
- 不把「代理指标」说成事实：涉及打架/运营的结论必须带「终局面板代理」或「证据不足」。
- 样本 <3 局：不给趋势、不给胜率结论，只写「单局参考」。
- 不评价选手个人好坏；只描述职责与结构。
