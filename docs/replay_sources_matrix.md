# 回放的四个来源：各自能给什么、给不了什么

- 日期：2026-11-10
- 目的：教练问「这一项为什么是空的」时，能直接查到该去哪一路取数；也是「.abc 能不能研究透」的判断依据。
- 证据：`docs/evidence_audit.md`（逐字节对拍与推翻记录）、`docs/analysis_fields_matrix.md`（营地回放 22 局字段覆盖率）、`docs/replay_binary_format.md`（容器与帧命令）。

四路来源不是替代关系，是分辨率不同的四层：

```
.abc/.ope 文件      15 帧/秒（引擎实测 15.1515，待对拍）   输入层：谁在什么时候按了什么
营地网页回放        位置 1 Hz / 经济 ~30 s / 事件级   结果层：谁在哪、打了多少
录屏 OCR            采样帧率（默认 1 fps）   画面层：屏幕上看得见的一切
结算截图            终局一帧   汇总层：最终面板
```

## 2. 各路的硬边界（都有对拍记录，不是估计）

### `.abc/.ope`：它是 lockstep 输入回放，不是录像

文件里写的是**输入**（帧命令），不是**状态**。这决定了它的上限：

- ✅ 能解：容器、十人名单/阵营/槽位、1251 胜负/MVP/评分、购买与技能升级、朝向、稀疏位置锚点、操作流事件。
- ❌ 解不出：KDA、逐笔金币、血量、伤害。**不是没解出来，是没写进文件**
  （`docs/evidence_audit.md` §1.3、§3；`COMDT_GAME_30SEC_INFO` 是客户端→服务器协议，回放容器 0 命中）。
- ⚠️ 位置：`0x82 kind=2` 是英雄自身世界坐标的稀疏锚点，只覆盖 3/10 人、90/10,509 帧（0.86%）；
  方向积分成轨迹已证伪（锚点残差 1.8 万–6.5 万，`docs/replay_binary_format.md` 5.132）。

### 营地网页回放：结果层，但不是逐秒逐人

- ✅ 1 Hz 位置（10 人 × 693 秒）、团队金币 ≈30 s、KDA/评分、团战与死亡事件。
- ❌ 没有逐人 1 秒金币，没有原始输出/承伤，没有逐帧血量。
- 与面板对拍：团队金币 41,021/29,266 vs 面板 41,000/29,248（差 21/18 g），KDA 10/10 一致。

### 录屏 OCR：唯一能补血量和连续轨迹的一路

- ✅ 可见即所得：血条、小地图、面板、记分板。
- ❌ 精度受采样帧率和遮挡限制；`estimated`，不能当逐字节真值。

### 结算截图：只给终局

- ✅ 十人 KDA/经济/输出/承伤/参团的终局总量。
- ❌ 没有任何过程信息。

## 3. 「.abc 能不能研究透」

分三档回答，别混在一起说：

| 层 | 状态 | 结论 |
|---|---|---|
| 容器 / 名单 / 评分 / 胜负 | 已解，逐字节对拍 | **研究透了** |
| 指令层（购买、技能、朝向、落点、移动方向） | 已解大部分；`BOOTFRAP selector 26` 等少数标签未解 | **能解完**，是工作量问题，不是可能性问题 |
| 状态层（KDA / 金币 / 血量 / 伤害 / 连续轨迹） | 文件里没有 | **解不出来**。只能跑引擎模拟，而 G1–G5 五项验收一项未过（`docs/evidence_audit.md` §2.1） |

一句话：**输入层可以做到 100%，状态层是 0%，中间没有捷径。**
想补状态层，正确顺序是「营地接口 → 录屏 OCR → 结算截图」，而不是继续堆宿主模拟。

## 4. 复现

```powershell
python scripts/replay_probe.py "data\replays\<局>.abc"        # 容器 + 名单 + 事件计数
python scripts/import_camp_replay.py "<营地链接>"              # 营地回放入库
python scripts/replay_video_ocr.py "<录屏.mp4>" --fps 1        # 录屏 OCR
python -m pytest tests/test_replay_samples_pinned.py -q        # 真实样本回归
```
