# `.abc` 初始化标量块（443 B）差分审计

日期：2026-11-13。范围：只读本地回放文件；不启动/连接游戏，不注入，不读进程内存。

结论先行：**这个块里 110 个 u32 只有 3 个能命名**（1 modeWord、2 initialGold、
67 server time）；其余 107 个保持未命名。这轮新增的是**可复现的定位方法与差分分类**，
不是给字段套名字。

## 1. 位置与定位方法

块紧跟在 `svr2GamecoreCfg` KV 数组之后：

```text
kv_start        u16LE count（观测恒为 53），随后 count × 4 B {confType:u8, value:u16BE, pad:u8}
scalar block    110 × u32 BE（440 B，大端）
terminator      1–3 B，随构建不同：11/1 是 0a，11/2 是 00 00 0a
player block 0  camp=1, echo=1, 0x01, slot=0, 0x0000, entityId:u16BE
```

定位**不依赖**固定偏移或固定终止字节（两者都随构建/队长变化）：

1. 在 `0x100..0x4000` 里找 confType 序列 `1..10`（每 4 字节一个）——与取值无关，所以
   不同模式的 KV value 都能命中；
2. 读 count，算 `base = kv_start + 2 + count*4`，在 `base-4..base+8` 里选对齐；
3. 用 11 个**锚点词**打分（`docs` 里从未把锚点当字段名）：`w0=0, w2=300, w3=1000,
   w4=7, w5=5, w6=2, w7=10, w8=5, w9=1, w10=66, w11=1000`；
4. 用第一个玩家块签名确认块尾，并要求中间 1–3 字节属于 `{0a, 000a, 00000a}`。

实现：`abc_init_block.py`（`locate` / `kv_pairs` / `known_fields`）。
审计：`scripts/audit_scalar_block.py`。

## 2. 样本覆盖

本地 33 个 `.abc`，**14 个**命中上述布局，全部锚点 `11/11`：

| 项 | 观测 |
|---|---|
| KV count | 53（全部） |
| KV mode（confType 1） | 50（全部，正常 5v5） |
| scalar_start | 608 / 609 / 611 / 612 / 613 / 666 / 668 |
| terminator | `0a`（4 个）、`00000a`（10 个） |
| mapType / mapId | 1→20041（4 个）；3→20011（3 个）；3→20111（7 个） |
| 不同标量块 | 12 种 |

其余 19 个是**另一种容器布局**（没有 1..10 confType 头，含 2025-12、2026-04 的老样本
与若干 2026-08 样本），本工具明确报 unsupported，不猜偏移。

支持矩阵按地图/模式分：

| mapType | mapId | 样本 | 支持 | 说明 |
|---:|---:|---:|---|---|
| 3 | 20111 | 7 | ✅ | 常规 5v5 |
| 3 | 20011 | 3 | ✅ | 常规 5v5（另一张图） |
| 1 | 20041 | 4 | ✅ | 另一模式；标量块中 7 个词与 5v5 不同 |
| 9 | 5466 | 1 | ❌ | KV 结构相同，但标量块是另一套（大面积 0，玩家块前移 437 B） |
| — | 1010 / 无 / 老构建 | 18 | ❌ | 容器布局不同，无 1..10 confType 头 |

**非 5v5 模式不强行解析**：`mapType=9` 的标量块与 5v5 不是同一结构，硬套锚点只会
产出假的字段值。产品只关心 5v5，这类样本按 unsupported 处理。

## 3. 差分分类（14 个样本）

| 类别 | 词数 | 说明 |
|---|---:|---|
| 恒定 | 95 | 14 个样本逐字节相同 |
| 少量变体 | 14 | 2–8 种取值 |
| 逐局变化 | 1 | 只有 index 67 |

字节级：**46 个非零常量字节、367 个恒零字节、27 个可变字节**。
块的平均信息密度很低，后段大面积为 0。

## 3.5 KV 数组差分（53 项）

同一批 14 个样本的 `svr2GamecoreCfg` KV（53 个 `confType → confValue`）逐项比对：

- **53 个 key 的取值在 14 个样本里全部相同**，没有任何一项随对局变化；
- `94=70`、`95=8` 在这批样本里也是常量（既有文档记录的「随模式变化」在这批 5v5
  样本里没有出现，因为样本全为 5v5）；
- 53 项拼接后的 SHA-256 在 14 个样本里**只有一个值**
  （`57372801f8840380…`）。

因此 KV 是**模式/构建级规则集**，不是逐局数据。它的用途是给回放打「同一套规则」的
指纹：指纹变了，跨局比较就要注明规则不同。测试
`test_kv_ruleset_is_constant_across_supported_samples` 固定这一点。



## 4. 已确认的锚点

| index | 值 | 依据 |
|---:|---|---|
| 2 | 300（恒定） | 与 KV 7/19/80 = 300 一致；文档既有结论 `initialGold` |
| 67 | 逐局 unix 时间 | **12 个样本全部**等于文件名里的服务器时间戳（1 个样本差 1 s） |
| 1 | 0x05559F20 / 0x05459D20 | 文档标签 `modeWord`，语义仍未定 |

index 67 的确认方式：从文件名取**最后一个** plausibly-unix 的 10 位段（文件名里
还有 relay 实体等 10 位数字，取第一个会错）。测试 `tests/test_abc_init_block.py`
把这条固定成 ±1 s 断言。

## 5. 与地图/模式一一对应的 7 个词

用「重复属性 → 单一取值」判定（要求属性至少 2 个取值、每组 ≥2 个样本、覆盖 ≥80%
样本；否则每局唯一的帧数会与一切“相关”）。命中：

| index | mapType=1 / mapId=20041 | mapType=3 / mapId=20011 | mapType=3 / mapId=20111 |
|---:|---:|---:|---:|
| 1 | 88448288 | 89497376 | 89497376 |
| 85 | 0 | 1048576 | 1048576 |
| 86 | 0 | 1025 | 1281 |
| 97 | 13 | 2 | 2 |
| 100 | 0 | 33554432 | 33554432 |
| 106 | 13 | 0 | 0 |
| 107 | 1 | 33554432 | 33554432 |

读法：`w1/w85/w100/w107` 按 **mapType** 分组；`w86/w97/w106` 按 **mapId** 分组。
所以这 7 个词是**地图/模式配置**，不是逐局状态——对「重建一局过程」没有增量信息，
但对「判断这份回放属于哪张图哪套规则」有用。

## 6. 仍未解释的 7 个词

`58, 83, 87, 98, 99, 108, 109` 在不同样本间变化，但既不跟 mapId、也不跟帧数分组：

```text
58   [96, 2144, 67680, 4194400, 16844896, 2168526944]    疑似位域/多字节打包
83   [0, 65536]                                           0x00010000
87   [512, 196608, 16843521]
98   [1, 10, 11, 14, 20]
99   [0, 1, 2, 3, 65538]
108  [131072, 167772160, 184549376, 234881024, 335544320]  多为 (10/11/14/20)<<24
109  [0, 16777216, 50331648, 67108864]
```

`98` 与 `108`、`99` 与 `109` 的取值集合高度重合（一个是右对齐、一个是 `<<24`），
一度像「同一逻辑值的两种存放」。**这个假设已被样本否证**：

| 样本 | w98 | w108 | w108>>24 | w99 | w109 | w109>>24 |
|---|---:|---:|---:|---:|---:|---:|
| 20261102_161129 | 14 | 0x0E000000 | 14 | 2 | 0x01000000 | 1 |
| 20261102_163751 | 14 | 0x0E000000 | 14 | 2 | 0x04000000 | 4 |
| 20261101_182452 | 1 | 0x00020000 | 0 | 65538 | 0 | 0 |

- `w99` 与 `w109>>24` 在多为 5v5 样本里就对不上（2 vs 1、2 vs 4），是**两个独立字段**；
- `w98/w108` 只在 mapType=3 时保持 `w108 = w98<<24`，到 mapId 20041 断裂
  （`w98=1` 而 `w108=0x00020000`），所以也不是同一字段的两种表示。

负结果已固定进测试 `test_scalar_word_pairing_hypothesis_is_disproven`，
避免后续再被当成结论推导。

## 7. 与 databin 对拍：没有命中

把 14 个样本的 48 个非零常量值与 825 张 databin 表（stride=4、行数 ≥8）逐值比对，
**没有任何表包含 ≥8 个相同的 4 字节行**。因此这个块不是某张 databin 表的直接导出，
不能靠表列名反推字段。

## 9. 边界

- 不把锚点词当字段名；锚点只用于选对齐。
- 不因为数值“看起来像”金币/等级就命名——`docs/abc_to_level_context.md` §10 已写明
  443 B 的顺序不等于 `CLevelContext` 声明顺序。
- 老布局样本不强行解析：报 unsupported，不猜偏移。
- 本轮未接触游戏二进制、未读进程内存、未改任何回放文件。
