# 回放录屏 OCR（实验）

对固定布局的本地回放录屏做只读文字识别：回放列表、加载页阵容、对局顶部计时/击杀/团队经济、底部所选面板、记分板逐人经济。只读取画面中已经出现的文字，不推算未显示的状态；不写数据库，不进入正式比赛和胜率统计。

## 录制要求与页面示例

每局一段完整录屏：加载页十人阵容约 5 秒 → 局内 00:00 开始的完整 1 倍速过程 → 水晶结束、胜利/失败动画 → 赛后战绩页约 5 秒。尽量始终打开双方十人 KDA/累计经济的团队面板；开局、每约 5 分钟及结束前有条件时补开完整记分板至少 5 秒。保留顶部时钟、击杀、双方金币，不裁切、不剪辑、不用单英雄可用金币代替累计经济。

[查看录屏面板布局示意和完整步骤](http://127.0.0.1:8766/assets/collection-guide.html?section=video)。一份 OCR 报告满足本局录屏数量要求，完整性由复核人对照起止和面板检查；不存在每局 11 份报告的要求。

## 适配范围

- 16:9 录屏，参考布局为 1600×900；其他 16:9 分辨率按宽度等比映射。
- 视频包含回放列表或加载页，以及完整的对局 HUD（顶部计时器 + 底部分析面板）。
- 画面语言为简体中文；UI 为本次样本的 12.1.x 回放界面。UI 改版需重新校准坐标。
- 解码依赖 `ffmpeg` / `ffprobe`；OCR 使用本机 `rapidocr-onnxruntime`，不调用云端图像服务。

## 使用

```powershell
python scripts/replay_video_ocr.py "C:\path\to\录屏.mp4" --fps 1
```

默认把报告写到 `data/replays/video_ocr/<视频 sha256 前 16 位>.json`。常用参数：

| 参数 | 说明 |
| --- | --- |
| `--fps 1` | 采样帧率。默认 1；`2` 更平滑但耗时约翻倍，`0.5` 更快但击杀时间精度降到约 2 秒 |
| `--abc PATH` | 同一局的 `.abc`。只读解析十人英雄集合，用于补全 OCR 未读出的英雄；不写数据库 |
| `--evidence DIR` | 保存列表、加载页、首/末 HUD、记分板、团队面板、赛后页等关键帧，便于人工核对 |
| `--ocr-engine rapid/mimo/auto` | `auto`（默认）在模型可用时加 Mimo 关键帧精读；`rapid` 只跑逐帧快速 OCR |
| `--out PATH` | 指定报告路径；`-` 表示只打印到终端，不写文件 |
| `--json` | 打印完整 JSON 而不是中文摘要；报告仍会写到文件（除非 `--out -`） |
| `--quiet` | 不显示采样进度 |

本次样本：

```powershell
python scripts/replay_video_ocr.py "<录像目录>\王者荣耀(1).mp4" `
  --fps 1 --abc data/replays/samples/20261028_135516.abc --evidence data/replays/video_ocr/evidence
```

1 fps 采样约 1–2 分钟；OCR 只读视频帧，不修改录像或游戏进程。

## 读取的字段

| 阶段 | 字段 | 约束 |
| --- | --- | --- |
| 回放列表 | 标题（本局昵称）、模式、日期时间 | 列表卡片可能被“确定观看”弹窗遮住，逐帧取信息最完整的一张；年份不在画面中，不推断 |
| 加载页 | 蓝/红双方各 5 名英雄、昵称 | 上方为蓝方、下方为红方；英雄名以印刷文字为准，单字差只列候选 |
| 对局顶部 | 局内时钟、双方击杀、双方团队金币、双方龙/塔计数 | 金币按 `k` 显示取整；左侧蓝方依次为龙、塔，右侧红方依次为塔、龙；只读团队累计数 |
| 底部面板 | 等级、KDA、可用金币、物攻/物防/法攻/法防、铭文文字、6 格装备的填充状态与候选名 | 面板跟随观战目标；录制中切换时按等级/KDA/属性跳变分段；铭文只在本地面板显示，末尾常被裁切；装备名只有达到 0.80/0.08 才作为候选 |
| 记分板 | 逐人 K/D/A + 累计金币 5×2 行 | 只在打开记分板时可见；行序可能按金币重排，按行内印刷名字认人；K/D 与顶部团队击杀/死亡交叉校验，A 按列位置保留但不独立校验；金币按两侧合计校验 |
| 团队面板 | 双方各 5 人的 KDA、累计金币 | 面板整局打开时逐秒读取；行序按队伍槽位；金币是累计经济，不是底部可用金币；装备留赛后 |
| 时间轴 | `videoTime`、`gameTime`、双方击杀/金币 | 视频时间与局内时间分开；停顿、跳变、倍速单独记录 |
| 一致性 | 顶部击杀/团队金币回退 | 两者都是累计值，回退读数按误读丢弃（保留原文并标 `suspect`），不写进时间轴 |

## 不读取 / 不能得到

- 输出伤害、承受伤害、参团率、推塔/资源明细（只读顶部团队龙/塔累计数）、位置/轨迹、技能命中、装备特效：画面未显示，或小字/图标不足以稳定读取。团队面板的装备逐秒不读，留赛后最终画面。
- 未打开记分板时的逐人经济。底部金币是**当前可用金币**，不是累计经济；两者不能混用。
- 观战目标身份：底部面板没有印刷英雄名；分段只表示“这一段读数属于同一个面板”，不确认是哪名队员。
- 赛后结算与胜负：只有录像播放到结算画面才可能读取；本次录像在对局 01:46 结束，总时长 02:57。

## 布局与 ROI

参考坐标均为 1600×900 下的像素，代码见 `video_ocr.py` 的 `ROI` 常量。

| 区域 | 坐标 | 用途 |
| --- | --- | --- |
| 顶部计时 | `(756, 0, 836, 28)` | 场景判定与局内时间 |
| 双方击杀 | `(732, 8, 774, 52)` / `(824, 8, 868, 52)` | 中间 `0 vs 0` 两侧 |
| 团队金币 | `(576, 4, 674, 54)` / `(928, 4, 1024, 54)` | 含金币袋图标，解析时只取数字与单位 |
| 底部 KDA | `(388, 774, 474, 808)` | 半透明白字，先做白色掩码 |
| 底部可用金币 | `(1140, 756, 1200, 790)` | 金币袋下方数字 |
| 四项属性 | `(492, 716, 728, 752)` | 用橙色/紫色图标锚定四个数字区 |
| 铭文文字 | `(742, 758, 1115, 795)` | 只在本地面板出现；右侧常被面板裁切 |
| 装备槽 | `(795, 700, 840, 748)` 起，步长 60，共 6 格 | 金色图标是召唤师技能，不计入六格；V 均值 >85 判为有装备 |
| 游戏内侧栏 | `(0, 270, 165, 880)` / `(1435, 270, 1600, 880)` | 五条昵称，用于与加载页对齐 |
| 记分板 K/D/A 列 | `(548, 198, 736, 244)` / `(1306, 198, 1470, 244)` | 行距 123，共 5 行；KDA 行被底部面板遮挡时在快照前后 1.4 秒内以 5fps 重扫缺失行 |
| 记分板名字列 | `(170, 198, 480, 253)` / `(930, 198, 1240, 253)` | 行序会变，按印刷名字认人；剩余唯一队员可排除补全 |
| 记分板金币列 | `(744, 198, 800, 244)` / `(1498, 198, 1566, 244)` | 行距 123，共 5 行 |
| 团队面板 KDA/金币 | 蓝 KDA `(420, 699, 525, 733)`、金币 `(533, 699, 586, 733)`；红金币 `(1013, 699, 1065, 733)`、KDA `(1074, 699, 1180, 733)` | 行距 39，共 5 行；双方各 5 行；金币是累计经济 |
| 加载页卡片 | 中心 x=`296/546/796/1046/1296`；名字 y=`262–334`（蓝）/`755–834`（红） | 英雄名与昵称两行 |
| 场景标记 | 顶部计时器 / 中央 `VS` / 左上“本地回/观战” | 对局 / 加载 / 列表 |

底部四项属性用图标颜色定位，而不是固定切四个数字框：橙色（物攻、物防）与紫色（法攻、法防）图标的右边缘之后分别是数字区，这样数字位数变化不会被裁掉。属性为 0 时字形是一个小圆圈，OCR 会给出句号类结果，统一按 0 处理。

## 20:9 长屏与 Mimo 关键帧（2026-11-02）

新增 20:9 布局 profile（参考 1600×720），用于 960×432 等长屏录屏：

- 顶部计时/击杀/金币、左右昵称、加载页卡片、底部团队面板使用独立坐标；不是把 16:9 坐标直接拉伸。
- 20:9 底部团队面板更矮；快速 OCR 的 KDA 可能只能读到部分行。报告保留 `teamPanel.frames` 和 `06-team-panel-*.png`，由 Mimo 窄裁读取。
- Mimo 只读加载页两行卡片和团队面板关键帧；逐帧时钟/击杀/金币仍走快速 OCR。
- 团队面板窄裁为左/右 KDA+金币列，兼容“KDA 在前”和“金币在前”两种列序；每 60 秒取一个关键帧，最多 6 个。
- 录像末尾识别到“胜利/失败”“返回大厅/再看一局”等赛后页时，保存 `07-postgame-*.png` 证据帧；固定字段仍以同局赛后截图为准。
- 20:9 低清录屏的顶部金币/击杀会因小字和压缩产生回退读数；报告会标 `suspect` 并统计回退次数，不能当精确终局。
- 无同局截图/`.abc` 时，加载页英雄名可能被皮肤标题连读；英雄身份仍需人工确认。

## 团队面板（逐秒）

面板整局保持打开时，底部同时显示双方各 5 行：头像、KDA、累计金币、6 格装备。识别取 KDA 与累计金币，行序按队伍槽位绑定 `lineups[].panelSlot`；金币是**累计经济**，不是底部“可用金币”。装备逐秒不读，留赛后最终画面。

- 1 fps 输出 `teamPanel.samples`，每个样本含 `videoTime`、`gameTime`、蓝/红各 5 行的 `kda`、`gold`、`hero`、`nickname`。
- 首行作为开关门控；整帧至少 8/10 行可读才接受，避免把普通底部面板误认成团队面板。
- 面板未打开的时段没有逐人数据，回退到 `scoreboard.snapshots`。
- 行序若被 UI 改为按金币排序，`identity: "slot-order"` 会失效，需要改成头像/名字匹配。
- 参考坐标见 `video_ocr.py` 的 `TEAM_PANEL_*` 常量。

## 人工核对清单

1. 加载页英雄名是否与画面一致，尤其是单字差候选（本次“孙膑”“蚩奼”是靠 `.abc` 集合补全的）。
2. 团队金币是画面显示精度（`1.5k`），不要与底部“可用金币”混用，也不要当成精确到个位的经济。
3. 记分板行序可能变化（本次 01:00 按金币重排），身份按行内名字匹配，不能按行号推定；名字读不出时用剩余唯一队员补全。
4. 记分板 K/D 已与顶部团队击杀/死亡校验；助攻按列位置保留，未独立校验；被底部面板遮住的行只在团队 K/D 已对齐时补 0/0，助攻留空。
5. 底部面板分段表示“观战目标切换”，不代表某一名的完整时间序列；身份未由画面文字确认。
6. 时间轴跳变处是否对应录屏剪辑、暂停或跳转；跳变两侧不要当连续比赛时间。
7. 录像未播放到结束时不提供赛后总数据；本样本只覆盖到 01:46。
8. 顶部龙/塔计数是否与画面一致：左侧蓝方依次为龙、塔，右侧红方依次为塔、龙；只读团队累计数。

## 已知限制

- 固定布局：UI 改版、非 16:9、裁切、画中画、竖屏都会让 ROI 失效。
- 生僻字识别有限：本次“蚩奼”在加载页被读成“蛋/蚩妊”一类，必须靠候选或同局 `.abc` 核对；`.abc` 的阵营分组来自录屏，前五/后五顺序是推断，不是文件字段确认。
- 记分板逐人金币/KDA 只在打开时可见，是快照而非连续曲线；未打开时没有逐人经济或 KDA。行序可能按金币重排，不能按行号映射身份。
- 记分板最后一行可能被底部面板遮住；此时只能在其余行已对齐团队 K/D 的前提下补 0/0，助攻无法补。名字被逐字拆开时，整行 OCR 会合并、去重后再匹配；整行仍读不出时，才用剩余唯一队员排除。KDA 行淡出时会在快照附近重扫，但仍可能读不全。
- 团队面板按“行序 = 队伍槽位”绑定身份；若 UI 改为按金币排序，必须改成头像/名字匹配。面板关闭的时段没有逐人数据，只能回退到记分板快照；团队面板的装备逐秒未提取，留赛后最终画面。
- 底部面板没有印刷英雄名；分段只保证“同一段内的读数来自同一个面板”，不保证身份。
- 铭文文字只在本地面板出现，观战其他队员时不显示；文字右侧常被面板裁切，最后一个铭文名可能只是片段。
- 装备名来自图标检索，相似度达不到 0.80/0.08 时只记录填充状态，不提供名称；技能冷却数字、血/蓝条、召唤师技能名称未提取。
- 记分板的装备图标和“经验/经济”页签未提取（本录像只开了“战绩”页）。
- 团队金币按 k 取整，逐人金币虽为整数但仅来自记分板快照；两者都存在显示精度问题。顶部龙/塔只读团队累计数，不区分暴君/主宰或具体哪座塔。
- 未实现赛后结算页读取；未实现装备图标/技能图标的可靠识别。
- 本功能为实验分析，不进入正式比赛、英雄胜率或训练统计；报告与证据帧只保存在本机 `data/` 下。
