# 战队分析 · 胜负条件与结果指纹（规格 v1）

状态：规格（未实施）· 2026-11-15
定位：**战队分析，不是赛前简报**。回答「这支队伍在什么条件下会赢 / 会崩 / 会变」，不输出 ban/pick 推荐，不写因果。

---

## 0. 先看数据，再定方法

对 `team-10a445325ac9` 的 25 局（12 胜 13 负，对手视角）做可行性检查，结论决定了这一版能做什么、不能做什么：

| 检查 | 结果 | 结论 |
|---|---|---|
| 终局经济差（胜/负） | +5,833 / −5,372 | 与胜负同义反复，**不能当“获胜原因”** |
| 场均推塔（胜/负） | 6.8 / 3.4 | 同上，是结果不是原因 |
| 场均控龙（胜/负） | 2.8 / 2.1 | 同上 |
| 时长（胜/负） | 851s / 936s | 同上 |
| 蓝/红方 | 蓝 5–4、红 7–9 | **赛前条件**，可以做条件胜率 |
| 双方阵容组合 | 25 局 25 套本队阵容、25 套对手阵容 | **选手 on/off 不可分层**，不做 |
| 时间轴 / 禁选手序 / 版本 | 均无 | 开团、转线、BP 顺序、跨版本不能答 |

因此这一版的分析对象只有两类：

1. **赛前条件**（可预知、可干预）：边、双方阵容家族、英雄出场、时间段。→ 条件胜率与候选规律。
2. **结果指纹**（终局长什么样）：经济差、推塔、控龙、时长、输出/承伤。→ 只描述“赢局长什么样”，明确标注不是原因。

> 这是本规格最重要的口径：**不把终局统计包装成“胜负驱动因子”**。那是最典型的同义反复，教练一眼能看穿，也会毁掉数科的可信度。

## 1. 样本与口径

- 单位：一局（`team-deep.games[]` 的一条）。
- 样本：本队与该对手的 25 局；`opponentWin` 有值 25 局；无重复 `seq`。
- 视角：对手视角。`opponentWin=true` 记对手胜。
- 基线：`p0 = 12 / 25 = 48.0%`。
- 时间：2026-11-07 ~ 11-10；`version` 为空，不能做跨版本。
- 缺失：特征覆盖 <80% 的项不进入结论；单局缺字段不补 0，直接不计入该项分母并在“覆盖”里标注。
- 最小样本：`n≥4` 才展示；`n≥6` 才允许写“候选规律”；否则显示“样本不足”，只给原始局链接。

## 2. 特征分类

### 2.1 赛前条件（P，Pre-game）

| key | 定义 | 来源 | 备注 |
|---|---|---|---|
| `side` | 对手蓝/红方 | `games[].ownSide` 取反 | 二值 |
| `theirFamily` | 对手双人/三人位置组合家族（边野/中野/射辅/中辅/野辅/中野辅/…） | `lineups.pairs/triads` | 每局取该局实际组合；家族样本 <3 归“其他” |
| `theirSignature` | 对手五路类型签名 | `lineups.signature` 的逐局版本 | 18 条签名多为 1 局，只做“命中/未命中”展示，不做胜率排序 |
| `theirHero` | 对手某英雄出场/未出场 | `games[].sides.enemy.picks` | 只取总局数 ≥6 的英雄；on/off |
| `ourFamily` | 本队双人/三人组合家族 | `games[].sides.own.picks` + 英雄类型表 | 本队逐局组合，需后端派生 |
| `period` | 前 12 局 / 后 13 局（按时间） | `games[].day/start` | 粗粒度变化观察，不做 change point |

### 2.2 结果指纹（R，Post-game，只描述不归因）

| key | 定义 |
|---|---|
| `goldDiff` | 对手终局经济 − 本队终局经济 |
| `towers` | 对手终局推塔 |
| `dragons` | 对手终局控龙 |
| `duration` | 全局时长（秒） |
| `damage` | 对手五人英雄伤害合计 |
| `taken` | 对手五人承伤合计 |

这些指标**不进入**“条件→胜率”表，也不进入候选规律；只在“赢局指纹”里做胜/负均值对比，并配固定文案：**“这是赢局的结果特征，不是获胜原因。”**

## 3. 模块 A：赛前条件胜率

### 3.1 维度与分箱

| 维度 | 分箱 |
|---|---|
| 边 | 蓝方 / 红方 |
| 对手阵容家族 | 边野 / 中野 / 射辅 / 中辅 / 野辅 / 中野辅 / 边野辅 / 中射辅 / 野射辅 / 边中野；<3 局归“其他” |
| 对手英雄 on/off | 总局数 ≥6 的前 5 个英雄，with / without |
| 本队阵容家族 | 同对手家族；<3 局归“其他” |
| 时间段 | 前 12 局 / 后 13 局 |

### 3.2 每个切片的输出

- `n`、`wins`、`losses`、`rate`、`wilson95`（Wilson 区间）。
- 与基线 `p0` 的差 `delta`：用 Beta 后验蒙特卡洛（20,000 次）得到 90% 区间；不展示 p 值。
- 标记：
  - `n<4`：`样本不足`，只显示局数；
  - `n≥4` 且区间跨 0：`和整体看不出差别`；
  - `n≥6` 且区间不跨 0：`值得继续看`（仍不是“显著”）。
- 多重比较：对全部切片做 BH-FDR（q<0.1 才标“值得继续看”）；其余一律“观察”。

### 3.3 候选规律

只允许 **2 个赛前条件** 的组合，例如：

- `红方 + 保护辅`：6 局 5 胜（83%，区间 44–97%），比整体 +35 个点。
- `蓝方 + 呆射`：5 局 1 胜（20%，区间 4–62%），比整体 −28 个点。

规则生成：

1. 枚举单条件（命中/未命中）与两条件组合；
2. 过滤 `n≥5`、两个条件各自 `n≥4`；
3. 计算 lift（相对 `p0`）、Wilson 区间、BH q；
4. 按 lift 的区间下界排序，最多展示 3 条；
5. 每条必须能点开对应局列表；没有证据的规则不显示。

**禁止**：用终局经济差/推塔/控龙/时长组合出“规律”（同义反复）。

### 3.4 交互

- 维度 chips 切换；行点击 = 交叉筛选。
- 选中条件写入 URL（`?wf=side:red&wf=family:保护辅`，可分享），并同步筛选：
  - 下方“相关局”列表；
  - 顶部“一句话画像”不改（避免整页跳动），只在本卡内显示“当前条件：红方 + 保护辅，6 局”。
- “清除条件”恢复全部 25 局。

## 4. 模块 B：赢局指纹

- 4–6 个结果指标，胜/负两组均值 + Hedges' g + bootstrap 95% 区间。
- 不排序为“驱动因子”，不写“因为”。固定标题：**“赢局长什么样（结果特征）”**。
- 文案示例：
  - “赢局终局经济 +5.8k，输局 −5.4k；赢局推塔 6.8，输局 3.4。”
  - “这些是结果，不是原因；赛前能改的是边、阵容和英雄。”
- 只在 `n≥4` 的组展示；否则显示覆盖不足。

## 5. 联盟先验与小样本收缩

目的：解决“1 局样本”“4 局 100%”的信任问题，不改变页面已有的证据门槛。

### 5.1 先验来源

| 先验 | 来源 | 当前规模 |
|---|---|---|
| 英雄出场/胜率 | `v3/bp-board` 104 局（双方 picks + 结果） | 104 局 |
| 双人/三人组合胜率 | `studio/camp-combos?min=3`（104 局） | 104 局 |
| 五路类型/阵容家族 | `bp-board` picks + 英雄类型表（后端映射） | 104 局 |
| 风格分位（top1Share / fight / macro） | `studio/teams.style.pool` | 全池 |

### 5.2 收缩

Beta-Binomial：

```
α0 = p_league * κ
β0 = (1 - p_league) * κ
posterior mean = (wins + α0) / (games + α0 + β0)
90% interval   = Beta(α0+wins, β0+losses) 的 5% / 95% 分位
```

- `κ = 8`（相当于 8 局先验）；联盟样本 <30 时 `κ = 4`，并在“怎么算的”里注明。
- 用途：
  - 英雄/组合胜率：显示后验均值 + 90% 区间；
  - 对抗矩阵：1 局格用联盟同类型对位做先验收缩，区间过宽就显示“证据不足”；
  - 不做“ban 推荐”，只显示条件胜率与区间。

### 5.3 不做“相似队伍对阵证据”

当前 25 局全部是本队 vs 该对手，其他队伍没有和该对手的交手记录；相似队伍只能做**风格参照**，不能当对阵证据。规格里不出现“相似队伍打它怎样”。

## 6. 统计规则（硬性）

- 胜率区间：Wilson 95%。
- 均值差：bootstrap 2,000 次（固定种子，按局重采样），百分位区间。
- 效应量：Hedges' g（小样本校正）。
- 多重比较：BH-FDR，q<0.1 才允许“值得继续看”。
- 最小样本：展示 4，结论 6；不足只给局数。
- 文案禁用：显著、证明、因果、必然、导致、说明（改为“关联/更常见/区间跨 0/看不出差别”）。
- 所有百分比必须带 `n`；所有结论必须能下钻到局。
- 方法说明收进“怎么算的”（折叠），教练层不出现 Wilson/bootstrap/Beta 字样。

     "wilson": [43.6, 97.0], "lift": 35.3, "q": 0.06, "gamesRef": ["..."]}

## 9. 验收

### 数据

- 25 局全部进入 `sample`；`conditions` 每个切片的 `games` 之和 = 25（同一维度内）。
- `patterns` 只含赛前条件；不含 `goldDiff/towers/dragons/duration`。
- 所有 `rate` 与 `wins/games` 一致；Wilson 区间包含点估计。
- 同一数据戳下重复请求结果一致（固定种子）。

### 统计单测

- Wilson 已知样例；Beta 后验均值/区间；BH q 值；bootstrap 固定种子快照。
- 规则枚举：支持度过滤、条件互斥、lift 方向。

### 页面

- QA 脚本新增：
  - `data.win_conditions_schema`（字段齐全、25 局、基线 48%）

  - `interaction.win_condition_filter`（点“红方”后相关局数变化、URL 带条件）
- 桌面/手机无横向溢出；深色主题对比度通过。
- 禁用词检查扩展到：因果、证明、显著、导致、必然。

## 10. 这一版不做

| 不做 | 原因 |
|---|---|
| 选手 on/off | 25 局 25 套阵容，无法分层 |

| 相似队伍对阵证据 | 没有其他队与该对手的交手 |
| 预测模型 | 104 局/4 队，队伍强度混杂；先做条件描述，不做概率预测 |
