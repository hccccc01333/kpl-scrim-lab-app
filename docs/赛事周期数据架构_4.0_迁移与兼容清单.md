## 2. Alpha 1 已落地的改动

### 2.1 新增表（`workspace_store.SCHEMA`）

```sql
event_cycles(
  id, name, prep_start, prep_end, official_start, official_end,
  status, source_competition_id, notes, created_at, updated_at, revision
)
```
四个日期即 4.0 方案的核心配置；写入时强制校验「正赛窗口 ⊆ 备赛窗口」。

### 2.2 仅增列（旧库自动迁移，`ensure_schema()`，幂等）

| 表 | 新列 | 用途 |
| --- | --- | --- |
| `competitions` | `event_cycle_id` | 旧单场配置归属到赛事周期 |
| `schedules` | `event_cycle_id` | 训练安排归属 |
| `match_records` / `matches` | `event_cycle_id` | 对局直连赛事周期（事实源） |
| `training_series` | `event_cycle_id` | 系列赛归属（与 `competition_id` 冗余校验） |

只执行 `ALTER TABLE ... ADD COLUMN`；不删表、不重建、不改旧列语义。写入通道
`upsert_match(event_cycle_id=...)`、`create_series(event_cycle_id=...)` 已支持。

### 2.3 旧数据迁移

`Workspace.backfill_event_cycles(dry_run=True/False)`：
- 为每个尚无周期且未挂周期的 `competitions` 生成一条 `event_cycles`；
- 映射：`date → prep_start`、`end_date → prep_end`、`formal_from/to → official_*`，缺值用备赛窗口兜底并在 `notes` 标注待核对；
- 回填 `competitions.event_cycle_id`，写 `change_log`，可重复执行不产生第二份；
- 正赛窗口越界的旧数据**原样保留**，只在返回结果给警告，不静默改时间。

接口：`POST /api/studio/workspace/event-cycles/migrate`（默认预演，`{"commit": true}` 才写库）。

### 2.4 全局数据范围解析层（新模块 `event_scope.py`）

```
赛事周期 event_cycle_id
   ├─ 直连：match_records.event_cycle_id
   └─ 间接：其下 competitions 的既有双口径（competition_scope_keys）
        ↓
   keys（明确归属）  +  provisional（仅日期命中，默认不进统计）
        ↓
   SQLite / 营地 JSON / 回放 / 事实缓存 一律按 Match Keys 过滤
```

关键约束：备赛周期重叠时**不能凭日期猜归属**，所以日期命中的对局单独放入
`provisional`，`strict=True`（默认）不进统计，需教练确认后转明确归属。
公开 KPL 参照数据、巅峰大盘、英雄克制知识库不经过这一层，切赛事周期不会被清空。

### 2.5 接口与前端

- `studio_api.py` 新增 `/api/studio/workspace/event-cycles*` 全套 CRUD、`current`、`scope`、`migrate`。
- `v3/serve.py` `repository()` 支持 `eventCycle`（优先于 `competition`），`filters()` 带回显字段。
- `v3/public/app.js` 顶栏新增赛事周期选择器，所有 `get()` 请求自动带 `eventCycle`；
  选择器状态存 `localStorage['training-current-event-cycle']`，切换派发 `event-cycle:selected`。

## 2A. Alpha 2 已落地：时间化身份与本队/对手管理

### 新增/扩展的数据结构

| 对象 | 处置 | 说明 |
| --- | --- | --- |
| `player_team_history` | **只加列** | `membership_id / relation_type / roster_role / actor / undone_at / notes`；原复合主键 `(player_id,team_id,start_date)` 不变 |
| `players.status` | 加列 | `active / archived`，合并只归档，不物理删除 |
| `account_player_links` | 新表 | 账号—选手的**时间化**关系：`valid_from/valid_to`、单局覆盖 `game_match_key`、阵营、撤销标记。旧的 `player_accounts` 仍是当前映射快表，不改其 `UNIQUE(platform,account_id)` |
| `identity_merge_logs` | 新表 | 重复选手人工合并的镜像与撤销依据 |

### 身份解析优先级

`单局覆盖(account+gameMatchKey) → 时间区间(account+日期) → player_accounts 当前快表`。
单局覆盖不参与按日期解析，避免一次身份纠错污染整段时间。

### 新能力

- `add_membership / list_memberships / undo_membership`：试训、转正、转会按生效日收口旧关系；撤销转会恢复原战队，不重写历史对局。
- `add_account_link / list_account_links / resolve_player_at / undo_account_link`：账号换人、一人多号、单局身份纠错均可追溯与撤销。
- `batch_create_role_players`：对手一键生成对抗路/打野/中路/发育路/游走五个本地 ID，重复执行幂等。
- `merge_players / undo_merge`：只搬映射与关系、归档来源选手、把来源名写入别名，**不改写 `match_rosters` 等历史出场事实**；可一键撤销。
- 接口：`/api/studio/workspace/identity/{memberships,account-links,resolve,players/roles,players/merge}`；数据准备页「选手主数据」新增一键五路 ID 按钮。

### 兼容性注意

- `matches` 是 `server.py` 的旧 JSON 对局表（`id/revision/body` 三列），全库大量位置参数 INSERT，**不对其加列**；赛事归属只落在权威表 `match_records`。迁移清单因此从 5 张表收敛为 4 张。
- 旧库 `player_team_history` 缺新列时，`ensure_schema()` 只做 `ALTER TABLE ADD COLUMN`，索引在加列后再建，避免 `CREATE INDEX` 因列不存在中断整个 SCHEMA 脚本。
- `players` 旧库缺 `status` 时同样只加列，默认 `active`。

### 回归结果（Alpha 2）
- `tests/test_identity_timeline.py`：**6 passed**（时间线、优先级、幂等建档、合并撤销、旧库迁移、API）
- 曾因给 `matches` 加列导致 `test_rename_sync.py` 2 例失败，已按上述原则修复；`test_rename_sync + test_event_cycles + test_identity_timeline + test_competition_scope` 共 **22 passed**。

## 2C. Beta 核心联动改造

### 全站赛事范围收窄的关键修复
`analysis_api.CompetitionScopedRepository` 原实现只在 `filters.competition` 存在时才按
Match Keys 过滤。赛事周期是全局上下文、请求只带 `eventCycle`，因此原逻辑会让分析页
**看似切换了赛事、实际仍统计全库**。已修正：
- `CompetitionScopedRepository(..., always_scope=True)`：传入赛事周期时强制过滤；
- `analysis_api.scoped()` 与 `v3/serve.py::repository()` 都按 `event_scope` 解析出的
  Match Keys 构造仓库，且周期优先于旧 `competition`；
- 只覆盖 `_selected_rows`，不改 `analysis_data.py` 的任何查询实现，所有走统一筛选口径
  的端点（matches/teams/players/heroes/bp…）自动生效。

回归用例：`/api/analysis/matches?eventCycle=<id>` 只返回该周期内的对局。

### 正赛入库补齐归属
- `/api/studio/official-entry` 修正了 v3.0.1 中 `competition_id` 漏定义被 `except` 静默
  吞掉的问题，并从 payload 或当前赛事周期取 `eventCycleId` 写入 `match_records`。
- `/api/studio/official-entry/import`（Excel 三 sheet）随所属 competition 继承
  `event_cycle_id`；`Workspace.save_formal_match(..., event_cycle_id=)` 支持该字段。

### 变更文件
`analysis_api.py`、`v3/serve.py`、`studio_api.py`、`workspace_store.py`、
`tests/test_event_cycles.py`。

### 仍未纳入本轮范围（Release 前待办）
- `/api/v3/space`、`/api/v3/economy` 走 `v3/deep_analysis.py` 直接读整库回放/营地目录，
  尚未按 Match Keys 收窄。这两处要改就得动空间/经济分析的输入装载层，违背本轮
  「不重写既有分析算法」的边界，留到 Release 前单独评估。
- 历史数据回填演练、真实有授权营地账号验证（`head.acntCamp` 视角、`playerId`
