# 赛训数据平台 V3 使用指南

2026-11-08。V1 工作台和 V2 独立服务已退役；本指南只描述 V3。

## 启动与入口

首次运行 `安装依赖.bat`。日常启动用 `启动工作台.bat`（或 `启动工作台-后台.vbs`），然后打开：

<http://127.0.0.1:8766/>

根路径就是 V3。`/v3`、`/studio`、`/analysis` 都是旧链接，会自动 302 回根路径。停止用 `停止工作台.bat`。

数据默认在 `data/`：数据库 `data/training.sqlite3`，对局包、导入、官方回放、V2 时间轴各有子目录。备份/恢复接口仍在 `/api/backup`、`/api/restore`；本机健康检查见 <http://127.0.0.1:8766/api/health>。

> `v3/serve.py --port 8771` 只用于开发和演示，不是产品入口；它不带采集写接口。

## 一级入口

V3 顶部按对象和任务组织：

- **营地同步**：`#ingest`，采集主路径。
- **对局档案**：`#matches`，含智能找局、精选对局、训练纪录、版本对比。
- **战队档案**：`#teams`。
- **选手**：名单与状态、选手认领、选手与位置、选手对比。
- **英雄**：英雄榜、英雄对比、英雄组合。
- **BP**：BP 概览、战队 BP、教练档案。
- **建档与训练**：建档、对手归属、待确认、约定计划、训练效果、分析报告。
- 深入分析分散在对应对象页面内，按主题进入。

页面顶部的「数据范围」控制来源、日期、对手、英雄、本队/全部等筛选。图表和卡片优先，明细表默认收起。

## 采集

采集只有一个主页面「营地同步」：

| 来源 | 档位 | 入口 |
|---|---|---|
| 官方回放链接 | 唯一必采 | 在校对页关联 |
| 营地数据自动采集 | 推荐主路径 | `#ingest` |
| 七张赛后截图 | 兜底 | `#shots` |
| 完整录屏 | 兜底 | `#videos` |
| 标准表格 | 选填·补充 | `#capture` |

采集总览每条通道行有「校对 →」，进入 `#review/<channelId>`：

- 对局信息、素材来源状态、10 行 × 9 个可编辑字段；
- 每个字段带来源与置信度，跨来源冲突折叠展示；
- 填写复核人并标记复核后，才能保存到正式统计；
- 昵称不能在草稿里改，身份问题走「选手认领」。

回放文件（`.abc` / `.ope`）解析口径未定，界面保留研究中页面，不作为采集来源。

## 演示数据

顶部「演示数据」会启动 8773 端口的独立演示库，页面带演示标记，不写入真实赛训库。点击「返回真实数据」切回。

## 遇到问题

- 页面还是旧布局：Ctrl+F5 强制刷新。
- 连接失败：确认启动窗口还在运行，打开 `/api/health` 查看进程和路径。
- 采集页提示「采集接口未挂载」：说明打开的是 `v3/serve.py` 的独立端口，不是 `server.py` 的 8766 根路径。
- 分析为空：先检查数据范围、来源筛选、采集是否已复核保存、选手身份是否已绑定。
- OCR 识别不完整：保留原图，人工校对；不要用猜测补全字段。详见 [OCR 引擎说明](ocr_engine.md)。
