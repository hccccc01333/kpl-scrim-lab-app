# 赛训数据平台 V3 使用指南

2026-11-08。平台只有一个 V3 应用；旧版入口与命名均已下线。

## 启动与入口

首次运行 `安装依赖.bat`。日常启动用 `启动工作台.bat`（或 `启动工作台-后台.vbs`），然后打开：

<http://127.0.0.1:8766/>

根路径就是 V3。`/v3`、`/studio`、`/analysis` 都是旧链接，会自动 302 回根路径。停止用 `停止工作台.bat`。

数据默认在 `data/`：数据库 `data/training.sqlite3`，对局包、导入、官方回放、出装时间轴各有子目录。备份/恢复接口仍在 `/api/backup`、`/api/restore`；本机健康检查见 <http://127.0.0.1:8766/api/health>。

> `v3/serve.py --port 8771` 只用于本地开发调试，不是产品入口，也不带采集写接口。演示数据走 8773 端口的完整单应用（`server.py` + 隔离的 `KPL_DATA_DIR`），采集链路齐全。

## 第一次打开

空库时首页不是一页 0 局，而是三条把第一局拿进来的路：

| 路径 | 适合 | 说明 |
|---|---|---|
| 扫码采集 | 已经在打训练赛 | 教练号扫码一次，之后拉取最近训练赛，BP 与十人面板最完整 |
| 看一场示例 | 还在评估 | 30 秒打开隔离的演示库，不写入真实数据 |
| 导入表格 / 截图 | 没有营地授权 | 从赛后表格、七张截图或录屏开始 |

页面底部显示真实数据目录，可一键打开。装在安装版、但数据还在旧免安装目录里时，首页会自动发现旧库（桌面 / 下载 / OneDrive 桌面与下载下的 `KPL赛训工具`、`KPL训练赛项目`），显示局数与更新时间，点「搬到这台电脑」即整库搬迁：回放与录屏可勾选，SQLite 走备份接口复制，写完才合并进数据目录，失败不留残留、可直接重试。旧目录不会被改动；当前库已有对局时不会执行，避免覆盖。

不在这几个位置时，展开「旧数据在别的位置」粘贴目录路径（要包含 `training.sqlite3`）即可。

## 一级入口

V3 顶部按对象和任务组织：

- **营地同步**：`#ingest`，采集主路径。
- **对局档案**：`#matches`，含跨局分析、智能找局、精选对局、训练纪录、版本对比。
- **战队**：战队档案（`#teams`）、战队风格、战队阵容、战队训练。
- **选手**：选手档案（`#playerarchive`）、名单与状态、选手认领、选手与位置、选手对比。
- **英雄**：英雄榜、英雄对比、英雄组合。
- **BP**：BP 概览、战队 BP、教练档案。
- **赛训**：训练计划（默认）、数据准备（建档 / 对手归属 / 待确认）、复盘与报告（报告库 / 训练效果）；顶部「待处理」汇总待确认、战队待命名、旧名单未迁、训练课待复盘和历史对手 ID 未映射。
- **身份对照**：数据准备 → 建档 顶部。一行一个游戏账号，把营地昵称（游戏ID）改成机器人能认的选手ID 并归到战队；本队与对手都能改，一处命名后建档、对手归属、名单与状态、个人页都按这个名字显示。删选手会连他的游戏ID映射一起删。
- **对手 ID 映射**：待处理收件箱里可以把历史 `enemy_team_id` 映射到当前战队，映射后相关对局、训练课和周报一起生效。
- **训练课**：从训练计划点「训练课 →」进入，按绑定关系、日期 + 对手、日期 + 训练组依次关联对局；可手动挂局、查看对手简报（最近交手 / 常用英雄 / 禁用习惯 / 关键选手）、写训练目标、勾选出勤、保存赛后复盘，标记已复盘后计划自动完成。
- **报告导出**：训练课右上「导出报告」生成 A4 训练课报告；报告库可生成训练周报，均可导出 PNG 或打印/保存 PDF；周报带上周对比。
- **训练目标**：训练课目标支持绑定指标 + 目标值 + 达成 / 部分达成 / 未达成状态；绑定已接入指标后，保存时自动判定，报告里直接显示目标、实际值和达成表；出勤会写入训练课报告。
- **赛训看板**：训练计划页顶部集中展示近 8 周训练负荷、目标达成环、训练节奏热力、目标绑定/复盘/对局关联覆盖率和最近训练课；视觉只表达训练过程，不把胜率做主角。
- **赛训指标**：以训练过程为主（训练课 / 训练局 / 训练时长 / 目标达成 / 目标绑定覆盖率 / 复盘完成率 / 出勤 / 干预），对局胜率和场均时长只作为「对局上下文」，不塞进赛训主 KPI。
- **指标层**：`metrics_registry.py` 登记指标口径，`metric_service.py` 统一查询训练课/周指标；训练课页和周报读同一份结果，缺数据的指标返回原因而不是 0。
- 深入分析分散在对应对象页面内，按主题进入。

页面顶部的「数据范围」控制来源、日期、对手、英雄、本队/全部等筛选。图表和卡片优先，明细表默认收起。

## 战队

- **战队档案**：一队一卡；点进对手档案看五项得分、阵容、英雄池、BP、组合与逐局。
- **战队风格**：节奏 / 团战 / 运营 / 后期四项同池分位，四象限散点 + 风格榜。风格是相对值，样本不足 3 局只作参考。
- **战队阵容**：本队与对手的五人组、位置池与轮换；同一局两人同位置会标「位置重复」，不计入轮换。
- **战队训练**：按对手汇总训练课与交手日。训练课来自「训练计划」的排期（含训练目标与复盘状态），交手日从营地记录自动归集，不需要手工补。

## 采集

采集入口分两类：营地窗口内走「营地同步」；超过一个月、营地没有详情的老局在「截图 OCR / 录屏 OCR」里直接**新录入一局**。

| 来源 | 档位 | 入口 |
|---|---|---|
| 官方回放链接 | 营地路径必采 | 在校对页关联 |
| 营地数据自动采集 | 营地路径主材料 | `#ingest` |
| 七张赛后截图 | 补采 / 新录入均可 | `#shots` |
| 完整录屏 | 补采 / 新录入均可 | `#videos` |
| 标准表格 | 选填·补充 | `#capture` |

已有对局只是缺素材时用「补采到已有对局」；超过一个月、营地没有详情的老局用识别结果卡片上的「新建一局并录入」，七页截图齐全或一段十人阵容完整的录屏报告任一即可建档、审核、保存。

采集总览每条通道行有「校对 →」，进入 `#review/<channelId>`：

- 对局信息、素材来源状态、10 行 × 9 个可编辑字段；
- 每个字段带来源与置信度，跨来源冲突折叠展示；
- 填写复核人并标记复核后，才能保存到正式统计；
- 昵称不能在草稿里改，身份问题走「选手认领」。

回放文件（`.abc` / `.ope`）解析口径未定，界面保留研究中页面，不作为采集来源。

## 演示数据

顶部「演示数据」会在 8773 端口打开演示库。演示跑的是与真实工作台**同一份 `server.py` 单应用**：采集、导入、分析页面都在，只是 `KPL_DATA_DIR` 指向隔离的演示目录，写操作不会碰到真实赛训库。页面带演示标记，点击「返回真实数据」切回。

## 遇到问题

- 页面还是旧布局：Ctrl+F5 强制刷新。
- 连接失败：确认启动窗口还在运行，打开 `/api/health` 查看进程和路径。
- 进演示时提示「8773 上是旧版只读演示实例」：关闭旧的 8773 演示进程后重试（旧版独立只读端口）。
- 分析为空：先检查数据范围、来源筛选、采集是否已复核保存、选手身份是否已绑定。
- OCR 识别不完整：保留原图，人工校对；不要用猜测补全字段。详见 [OCR 引擎说明](ocr_engine.md)。
