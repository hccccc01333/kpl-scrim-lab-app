# 营地数据自动采集：部署与使用说明

2026-11-04。本流程通过营地官方接口拉取训练赛数据：教练一个账号授权后，
自动按选手增量拉取每局对局的完整数据（BP、十人面板、出装），不需要选手
做任何操作，也不需要截图识别数值。

## 一、这套流程的数据从哪来

```text
教练营地账号（扫码授权一次）
   │  ① 战绩列表：/game/morebattlelist（按选手、按水位增量）
   ▼
每局对局的五元组：gameSeq / gameSvrId / relaySvrId / battleType / 角色ID
   │  ② 对局详情：/game/battledetail
   ▼
data/camp_details/<gameSeq>.json
   BP 禁用、十人完整面板（输出/承伤/经济/补刀/打野经济/治疗/控制时长/
   对塔伤害/参团率/等级/评分/战力）、最终出装、团队金币
```

过程数据（团队金币曲线、事件、逐秒位置）另由**公开回放接口**提供，
两端可以互相校验。

十人面板里的 7 项扩展终局值（`killSoldier` / `monsterCoin` / `ctrlTime` /
`healCnt` / `buildingDamage` / `hurtTransRate` / `behurtPerDeath`）自 2026-11-05
起由 `channel_store.attach_camp_detail` 按 `docs/screenshot_fields.md` 的契约键
映射进采集通道草稿，随 bundle 落盘并进入跨局分析；教练无需额外采集七张截图。
字段口径与缺失处理见 [指标注册表](metric_registry.md) B 组。`data/camp_details/`
是只读原始样本缓存，不做回填改写。

## 二、需要准备什么（人工清单）

| # | 事项 | 谁做 | 频率 |
|---|------|------|------|
| 1 | 教练的营地账号一个（需绑定过游戏角色） | 教练 | 一次性 |
| 2 | 教练在营地 App 里**添加全部选手为好友/关注**，并确认能打开选手的营地主页 | 教练 | 一次性（新选手加入时补） |
| 3 | 选手战绩对教练可见：选手可不对外公开，在营地隐私设置里**把教练的账号加入可见白名单**（或直接保持公开）。工作台以"同步能拉到数据"为准 | 选手 | 一次性检查 |
| 4 | 确定 **1–2 个稳定上场选手的营地 ID**（找法见下一节）。`battledetail` 每局返回**十人全量面板（含对手阵营）**，所以一个每场必上的选手就是全队数据入口；若训练赛阵容轮换大，多配一个常上场选手兜底 | 教练 | 一次性 |
| 5 | 工作台里完成一次微信扫码授权 | 教练 | 一次性（token 失效后重扫） |
| 6 | 工作台"同步营地战绩"按钮 / 每日自动同步 | 教练 | 每天 |

## 三、营地 ID 是什么、怎么找

**营地 ID（`friendUserId`）是营地账号的数字 ID**（5–15 位数字），不是游戏
大区的角色 ID。两者都会出现在链接里，不要混淆：

| 名称 | 样例 | 出现位置 | 用途 |
|------|------|----------|------|
| 营地 ID | `540599032` | 分享链接的 `userId=` | 战绩列表的查询目标 |
| 角色 ID | `2081911312` | 分享链接的 `roleId=`、`uniqueRoleId=`、`toAppRoleId=` | 对局详情的 `targetRoleId` |

角色 ID 不需要人工收集——战绩列表每一条会自动带上当局的角色 ID。

**营地 ID 的找法（已验证）**：

1. 让这位选手（或教练代为操作选手手机）在营地 App 里**随便分享一局战绩**
   到微信，复制链接。
2. 链接形如
   `...mp-redirect/index.html?userId=540599032&roleId=...&gameSeq=...`。
3. `userId=` 后面的数字就是**这位选手的营地 ID**。只需一次，之后所有
   训练赛（只要他上场）都从这一个 ID 增量拉取；每局自动带全部十人。

工作台的批量粘贴入口会自动从链接里提取 `userId`，贴一条就完成登记。

注意：教练自己未绑定游戏角色的营地账号也能完成全部查询（实测），但
**扫码的账号必须能访问选手主页**（好友/关注关系）。

## 四、首次部署步骤

```powershell
# 1) 安装依赖（如尚未安装）
python -m pip install pycryptodome

# 2) 扫码授权：运行后弹出二维码，用教练的微信扫码并在手机上确认
python tools\camp_auth.py
#    成功后凭证写入 data\camp_auth.json —— 含登录态，勿入 git、勿外传

# 3) 首次同步（营地 ID 换成选手的）
python tools\camp_sync.py 540599032
#    data\camp_details\<gameSeq>.json 每局一份；水位记录在
#    data\camp_sync_state.json，之后只拉新局

# 查看授权状态 / 删除凭证
python tools\camp_auth.py --status
python tools\camp_auth.py --clear
```

多选手部署时，对每位选手的营地 ID 各执行一次第 3 步（或等工作台的
批量同步入口）。

## 五、日常使用

- 每天训练结束后（或第二天早上）在工作台点一次同步：每位选手只拉
  上次之后的新局，通常一两页请求。
- 每局数据包含 BP 与十人面板，映射进采集通道草稿后与截图/表格互校。
- **token 失效**表现为接口报 `-30314` / `-30003` 或安全参数被拒：重新运行
  `python tools\camp_auth.py` 扫一次码即可，历史数据不受影响。
- 工作台会自动检测登录态：进入采集页时跑一次轻量探测，拉取或入库时接口
  报登录态失效也会立刻记录。失效后「营地连接」卡片显示
  「营地授权已失效，爬取已暂停」，并把「补充授权」放在最显眼的位置；
  重新扫码后沿用原来的选手白名单，不需要重新登记。断网只会提示
  「暂时无法检测」，不会误判凭证失效。

## 六、故障对照（全部实测）

| 现象 | 原因 | 处理 |
|------|------|------|
| `-30003 登录态失效，请重新登录` | token 过期（2026-11-07 实测） | 重新扫码；工作台会自动提示「补充授权」 |
| `-30314 登录态参数不全` | token 过期或未扫码 | 重新扫码 |
| `encryptparamerr` 安全参数被拒 | 登录态失效 | 重新扫码 |
| `-102 用户ID不存在` | 营地 ID 填错（可能填成了角色 ID） | 核对第三节，用 `userId=` 的数字 |
| `-10102 获取用户角色信息失败` | 角色 ID 不匹配 | 该参数自动来自列表，重试；持续失败反馈开发 |
| 列表返回空但选手明明打过 | 该营地账号未绑定游戏大区角色 | 让选手在营地 App 里绑定角色后重试 |
| 报"召唤师隐藏了个人战绩" | 选手战绩对教练不可见 | 选手在隐私设置里把教练加入可见白名单，或恢复公开 |
| `hasMore` 为 true 但拉不到新局 | 正常：翻页上限 8 页，日常到不了 | 无需处理 |

## 七、边界与纪律

- 本流程只采集**授权选手清单内**的营地账号。接口技术上可查询任何战绩
  公开的用户，配置里限定选手白名单（通常 1–2 个稳定上场选手），不做通用查询。
  一局详情包含双方十人（含对手），对手数据仅随局入库，不单独追踪。
- 凭证与数据都保存在部署方（赛训组）自己的机器上，不上传第三方。
- 这是非官方接口：营地协议升级可能导致失效，届时客户端版本常量
  （`tools/camp_auth.py` 的 `CLIENT_CONSTANTS`）需要更新；公开接口
  （分享链接 + 回放数据）始终可用，作为降级路径。
